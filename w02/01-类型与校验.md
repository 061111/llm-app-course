### 0.3 概念地图：本节会出现 8 个词

读正文前先扫一眼。遇到不认识的词，回这张表查，不用往前翻。

| 术语 | 一句话定义 | 生活类比 | 在哪一节出现 |
| --- | --- | --- | --- |
| JSON | 一种文本格式：`{}` 表示对象、`[]` 表示列表、`"键": 值` 表示字段。模型输出的"结构化数据"基本都是它 | 全世界通用的表格模板 | 第 1 节 |

| 语义约束 | 字面合法、实际没意义（比如三个空格） | 表格里填了一堆"无无无" | 第 6 节 |
| 序列化 | 对象与 dict/JSON 的互转：`model_validate()` 把 dict 变成对象，`model_dump_json()` 反向导出 | 装箱与拆箱 | 第 9 节（导出见第 14 节速查表） |

## 1. 我们要解决的那一件事

你先看这段东西。假设你调用了一个大模型，让它根据资料回答「K-means 的 K 怎么定」，它返回的**原始文本**是：

````text
好的，以下是结果：
```json
{"answer": "K 需要预先指定，常用肘部法确定",
 "citations": [{"doc_id": "km-03", "quote": "K 值需人为设定"}],
 "confidence": "0.8"}
```
希望对你有所帮助！
````

你的程序需要从里面拿到三样东西：

| 你要的          | 类型        | 用途                                  |
| ------------ | --------- | ----------------------------------- |
| `answer`     | 字符串       | 显示给用户                               |
| `citations`  | 列表        | 每条含文档 id 和原文片段，用来做「点击查看出处」，也是防幻觉的证据 |
| `confidence` | 0 到 1 的小数 | 低于阈值就转人工，或者干脆拒答                     |

**这段文本里有三个坑，现在就埋着**：

1. 开头「好的，以下是结果：」和结尾「希望对你有所帮助！」是废话，不是 JSON
2. JSON 外面套了一层 ` ```json ` 围栏
3. `"confidence": "0.8"` 是**字符串**，不是数字

第 3 个最阴——它看起来像个数字，实际上带引号。如果你直接拿它做比较 `confidence > 0.5`，Python 会崩。

（JSON 是什么、`dict` 是什么，见 0.3 概念地图前两行。这里只要记住一件事：**模型给你的是"一段文本"，不是对象**——哪怕它长得像数据结构，它仍然是字符串。）

**这一讲的目标**：把这段脏文本，变成一个你**可以完全信任**的对象。什么叫信任？就是只要拿到了它，`answer` 一定是非空字符串、`confidence` 一定是 0~1 的数字、`citations` 一定是列表——不需要再检查。

## 2. 第 1 版：用 dict 接（会崩，且崩得很晚）

### 先回答一个必然的疑问：为什么要写一个会崩的版本

三个理由，按重要性排：

1. **它不是"跑不通"，是"跑通了、然后在一行上抛异常"。** 这两件事差别极大：能跑到那一行再崩，说明程序结构没问题，问题精确落在那一行。真正的"跑不通"是连解释器都进不来（比如你刚才那个 `[Errno 2]`）。
2. **你要的是它的失败特征，不是它的功能。** 就像做并行计算报告：你写串行版本不是为了交付它，是为了拿 baseline 算加速比、做正确性对照。这里 v1/v2 是所有后续版本的 baseline——没有它们，你说不出"v3 把错误提前了三个月"这种话。
3. **它的代码最后还在。** 最终 `schema.py` 第 69 行就是这一版的 `json.loads`，只是外面多包了一层剥围栏；v2 的 `answer: str` / `confidence: float` 两行一个字都没改。

### 这一讲的验收方式（每一版都这么测）

一个校验组件必须**喂两种输入各一次**，缺一不可：

| 输入                | 正确表现               |
| ----------------- | ------------------ |
| 好数据（干净 JSON）      | 通过，拿到正确对象          |
| 坏数据（围栏、空串、越界、编字段） | **报错**，且报错信息说得清哪里错 |

由此得出全篇最重要的判据：

> **对坏数据报错 = 功能正常；对好数据报错 = bug。**  
> v1 对坏数据不报错，所以它是坏的；v4 之后对坏数据报错，那是它在工作，不是它坏了。

所以「跑不跑得通」不能当验收标准，要看**它在哪种输入上崩溃、崩在哪一步**。

把 `try.py` 里原来的内容**全部删掉**，换成下面这几行（从这节开始，每次都是“整段替换”，不要往下追加）：

````python
import json

raw = '好的，以下是结果：\n```json\n{"answer": "x", "confidence": "0.8"}\n```'

data = json.loads(raw)
print(data["answer"])
````

跑：

```powershell
..\.venv\Scripts\python.exe try.py
```

输出：

```text
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

### 这行报错怎么读

| 部分                             | 含义                    |
| ------------------------------ | --------------------- |
| `json.decoder.JSONDecodeError` | 异常类型：JSON 解析失败        |
| `Expecting value`              | 期望看到一个值（数字/字符串/对象…）   |
| `line 1 column 1 (char 0)`     | 在**第 1 行第 1 个字符**就失败了 |

第 1 个字符是「好」——不是 `{`。所以它连第一个字符都过不去。

`json.loads` 是"把 JSON 文本变成 Python 对象"，它要求**整个字符串就是一个合法 JSON**，多一个字都不行。

### 洗掉围栏，再试一次

手动把脏东西删掉，假设你已经拿到了干净的 dict：

```python
data = {"answer": "K 需要预先指定", "confidence": "0.8"}

print(data["confidence"] > 0.5)
```

输出：

```text
TypeError: '>' not supported between instances of 'str' and 'float'
```

读法：`'>' not supported between 'str' and 'float'` = 「大于号」不支持在「字符串」和「小数」之间比较。因为 `"0.8"` 是字符串。

再试试拼错键名：

```python
print(data["answwer"])     # 多打了一个 w
```

```text
KeyError: 'answwer'
```

### 这一版的根本问题：不是会崩，是崩得太晚

这三个错误如果都发生在你眼前，那还好办。真正的麻烦是这个场景：

> 你把 `data` 传给下一个函数，下一个函数传给服务层，服务层写进缓存，三个月后另一个功能读出来做排序……  
> 这时候 `confidence` 是字符串，`>` 比较崩了。报错栈指向的是排序函数第 87 行，而罪魁祸首是三个月前那次模型调用。

**错误发生的地方（A）和报错的地方（B）隔得越远，排查成本越高。** 这是工程里最贵的一类 bug。

`dict` 之所以这样，是因为它就是"一袋没有形状的数据"：Python 不检查键存不存在、值是啥类型，你放什么它都收，你取什么它都试。

## 3. 第 2 版：class + 类型注解（有形状了，还是不检查）

既然 dict 没形状，那就给它定个形状。改用类：

```python
class AnswerV1:
    def __init__(self, answer: str, confidence: float):
        self.answer = answer
        self.confidence = confidence

a = AnswerV1(answer=123, confidence="很高")
print(a.answer, a.confidence)
```

输出：

```text
123 很高
```

**什么都没报。** `answer` 写的是 `str`，你传了数字 `123`；`confidence` 写的是 `float`，你传了 `"很高"`。全放行了。

### 逐行说明

| 行                         | 作用                           |
| ------------------------- | ---------------------------- |
| `class AnswerV1:`         | 定义一个类。这行只是"模具"，还没造出东西        |
| `def __init__(self, ...)` | 构造函数，创建对象时自动调用               |
| `self.answer = answer`    | 把参数存到对象上，之后 `a.answer` 就能取   |
| `answer: str`             | **类型注解**。注意它写在参数名后面，不是声明变量类型 |
| `AnswerV1(...)`           | 造一个对象，这时 `__init__` 被调用      |

> 你学过 Java/C++，那里 `String answer` 是编译器强制的。Python 的 `answer: str` **看起来像**那个，但**完全不是**。这是最容易误解的地方，下一节讲清楚。

### 插播：注解到底是什么东西

跑这一句：

```python
print(AnswerV1.__init__.__annotations__)
```

输出（真实结果）：

```text
{'answer': <class 'str'>, 'confidence': <class 'float'>}
```

注解被存进了一个叫 `__annotations__` 的字典里，键是参数名，值是类型对象。**然后 Python 就把它扔在那儿了，运行时不会拿它做任何检查。**

为什么？因为 Python 是动态类型语言，设计哲学是"鸭子类型"：只要这个对象能 `.strip()`，我就当它是字符串，不看你声明了什么。类型检查交给**注释性质的工具**（编辑器、mypy），不交给解释器。

### 那注解给谁用

| 消费者                        | 用它干什么         | 会不会拦你          |
| -------------------------- | ------------- | -------------- |
| 编辑器 / mypy                 | 自动补全、画红线、静态检查 | 只在写代码时提示，运行时不管 |
| 读代码的人                      | 知道每个参数该给什么    | ——             |
| **框架（Pydantic / FastAPI）** | **把它当规则执行**   | **会，而且当场报错**   |

第三行就是我们学注解的全部理由。注解本身是"说明书"，得有人愿意按说明书执法，它才有约束力。

**检查点 2**：`def f(x: int) -> str` 这个函数，传 `f("abc")` 会怎样？为什么？

## 4. 第 3 版：换成 `BaseModel`，注解开始执法

Pydantic 就是那个愿意执法的框架。改一个地方：基类。

```python
from pydantic import BaseModel

class AnswerV2(BaseModel):
    answer: str
    confidence: float

a = AnswerV2(answer="K 需要预先指定", confidence="0.8")
print(a)
print(type(a.confidence))
```

输出：

```text
answer='K 需要预先指定' confidence=0.8
<class 'float'>
```

三件事同时发生了：

1. **我没写 `__init__`，也没写赋值**，字段却自动有了
2. **`"0.8"` 变成了 `0.8`**，类型真的是 `float`
3. 打印出来是 `answer=... confidence=...` 这种格式（Pydantic 自带的）

再传那个 `"很高"`：

```python
AnswerV2(answer="x", confidence="很高")
```

输出：

```text
1 validation error for AnswerV2
confidence
  Input should be a valid number, unable to parse string as a number [type=float_parsing, input_value='很高', input_type=str]
    For further information visit https://errors.pydantic.dev/2.14/v/float_parsing
```

### 学会读 Pydantic 的报错（这个技能后面天天用）

| 行                                                                    | 含义                              |
| -------------------------------------------------------------------- | ------------------------------- |
| `1 validation error for AnswerV2`                                    | 有 1 个字段校验失败，出错的是 `AnswerV2` 这个类 |
| `confidence`                                                         | **出错字段名**。这一行是整个报错最有价值的部分       |
| `Input should be a valid number, unable to parse string as a number` | 期望数字，但给的是转不了的字符串                |
| `[type=float_parsing, input_value='很高', input_type=str]`             | 错误码、实际收到的值、实际类型                 |
| 最后一行 URL                                                             | 官方文档链接，搜这个 type 就有解释            |


对比第 1 版：dict 的 `TypeError` 只知道"str 和 float 不能比"，**不知道是哪个字段**。这里直接点名 `confidence`。

### 自动转换（coercion）的规则

这是一条必须记牢的规则，它决定了你后面写 LLM 代码时会不会崩：

| 声明      | 传入        | 结果                                        |
| ------- | --------- | ----------------------------------------- |
| `float` | `"0.8"`   | ✅ 0.8（字符串数字能转）                            |
| `int`   | `"18"`    | ✅ 18                                      |
| `float` | `"很高"`    | ❌ 报错                                      |
| `str`   | `123`（数字） | ❌ **报错**，`Input should be a valid string` |

最后一行反直觉，但很重要：**Pydantic v2 对"字符串→数字"宽松，对"数字→字符串"严格**。因为后者容易掩盖 bug（比如本该是 id 的整数被偷偷变成字符串）。

实测报错：

```text
1 validation error for AnswerV2
answer
  Input should be a valid string [type=string_type, input_value=123, input_type=int]
```

### 一句话总结这一版

> `dict` 是没形状的袋子；`class` 是有形状的袋子；`BaseModel` 是**带模具的盒子——形状不对的东西塞不进去**。

## 5. 第 4 版：`Field` —— 类型对了，值还是烂的

`answer: str` 只保证"是字符串"。但下面这些都合法：

| 传入             | 合法吗 | 合理吗        |
| -------------- | --- | ---------- |
| `""`           | 合法  | 不合理，空回答    |
| `"   "`        | 合法  | 不合理，看不见的字  |
| `"我" * 100000` | 合法  | 不合理，能把前端撑爆 |

所以 `str` 不够，要加**约束**：

```python
from pydantic import BaseModel, Field

class AnswerV3(BaseModel):
    answer: str = Field(min_length=1, max_length=2000)
    confidence: float = Field(ge=0.0, le=1.0)
```

`Field` 里常用的参数，这些够你用一整年：

| 参数                          | 含义                   | 适合                    |
| --------------------------- | -------------------- | --------------------- |
| `min_length` / `max_length` | 字符串/列表长度             | 回答、引用片段               |
| `ge` / `le`                 | 大于等于 / 小于等于          | confidence、分数         |
| `gt` / `lt`                 | 大于 / 小于              | 需要严格不等时               |
| `default`                   | 固定的默认值               | 数字、字符串、None、bool（不可变） |
| `default_factory`           | 传一个**函数**，需要时调用它造默认值 | 列表、字典；要同时加约束时         |
| `description`               | 说明文字                 | **会进 JSON Schema，见下** |

> `default` 只放不可变值（`0.5`、`"ok"`、`None`）。容器（list / dict）用 `default_factory`，原因不是"防共享"（Pydantic v2 会深拷贝，`= []` 也不会共享），而是：`= []` 后面接不上 `max_length` 之类的约束，而且每次构造要深拷贝一份。完整实测见本章末尾「检查点 4」。

跑两个失败：

```python
AnswerV3(answer="", confidence=0.5)      # min_length 触发
```

```text
1 validation error for AnswerV3
answer
  String should have at least 1 character [type=string_too_short, input_value='', input_type=str]
```

```python
AnswerV3(answer="x", confidence=1.5)     # le=1 触发
```

```text
1 validation error for AnswerV3
confidence
  Input should be less than or equal to 1 [type=less_than_equal, input_value=1.5, input_type=float]
```

### `description` 不是注释，它是给模型看的

```python
class AnswerV4(BaseModel):
    answer: str = Field(min_length=1, description="给用户的回答")
    confidence: float = Field(ge=0, le=1, description="0 到 1，低于 0.4 表示没把握")

print(AnswerV4.model_json_schema())
```

输出（真实，已简化排版）：

```python
{
  'properties': {
    'answer': {'description': '给用户的回答', 'minLength': 1, 'type': 'string'},
    'confidence': {'description': '0 到 1，低于 0.4 表示没把握',
                   'maximum': 1.0, 'minimum': 0.0, 'type': 'number'}
  },
  'required': ['answer', 'confidence'],
  'type': 'object'
}
```

`model_json_schema()` 把你写的类翻译成一份 **JSON Schema**（描述"数据长什么样"的标准格式）。

这份东西有什么用？**W5 的结构化输出、W12 的工具调用，都是把它直接发给模型**，让模型照着填。所以：

> 你在这里写的 `description`，模型真的会读。它不是给人看的注释，它是 prompt 的一部分。  
> 写「0 到 1，低于 0.4 表示没把握」，模型给的数就更符合你的预期；写「置信度」，它就只能瞎猜。

**检查点 4**：`citations: list[str] = Field(default_factory=list)` 里的 `default_factory` 和直接写 `= []` 有什么区别？

### 答案（以及一个和网上说法不一致的结论）

> **在 Pydantic v2 里，两者的行为没有区别——都不会共享。**  
> 「必须用 `default_factory`」这个规矩来自 `dataclasses`，不是来自 Pydantic。

实测（pydantic 2.14.1）：

| 写法                                              | 造两个实例，往第一个里 `append`  | 是否共享          |
| ----------------------------------------------- | --------------------- | ------------- |
| `tags: list[str] = []`                          | `x=['污染'] y=[]`       | 不共享           |
| `tags: list[str] = Field(default_factory=list)` | `x=['污染'] y=[]`       | 不共享           |
| 普通类 `def __init__(self, tags=[])`               | `p1=['污染'] p2=['污染']` | **共享（真 bug）** |

原因：v2 在构造每个实例时会把默认值**深拷贝**一份，所以同一个 list 不会在实例之间流通。而普通类的默认参数只在函数定义时创建一次，所有实例共用那一个 —— `dataclasses` 因此直接报 `ValueError: mutable default`，强制你写 `field(default_factory=list)`。Pydantic 沿用了这个写法习惯，但 v2 已经不需要它来防共享。

那为什么还写 `default_factory`？三个真实理由：

| 理由            | 具体说明                                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------------- |
| **想同时加约束**    | `= []` 后面接不上 `max_length=5`，只能写成 `Field(default_factory=list, max_length=5)`                                         |
| **类级默认值会被污染** | `= []` 那个 list 真实存在：`Answer.model_fields["citations"].default.append("脏")` 之后，所有新实例都带着它。`default_factory` 没有这个对象，改不动 |
| **深拷贝有成本**    | 实测默认值 2 万项时，构造 200 次：`=[]` 用 **2.88s**，`default_factory` 用 **0.26s**，差 11 倍                                          |

第四点更根本：**`default_factory` 能接受任意无参函数**，能表达「每次都不一样」：

```python
created: float = Field(default_factory=time.time)           # 当前时间
rid: str = Field(default_factory=lambda: uuid.uuid4().hex)  # 随机 id
citations: list[Citation] = Field(default_factory=list)     # 空列表
```

`= []` 只能是个固定值，后两种写不出来。

### 顺带一个更容易踩的坑：默认值默认**不校验**

```python
class T(BaseModel):
    tags: list[str] = Field(default_factory=lambda: ["a", "b", "c"], max_length=2)

T()   # 不报错！3 项超过了 max_length=2，但默认值不过校验
```

`max_length` 只管外部传进来的值。要让默认值也走校验，加上 `validate_default=True`：

```python
tags: list[str] = Field(default_factory=lambda: ["a", "b", "c"], max_length=2, validate_default=True)
```

## 6. 第 5 版：`field_validator` —— 规则引擎表达不了的判断

上一节留了个洞。试试这个：

```python
class NoBlankCheck(BaseModel):
    answer: str = Field(min_length=1)

print(repr(NoBlankCheck(answer="   ").answer))
```

输出（真实）：

```text
'   '
```

**通过了。** 因为 `"   "` 的长度是 3，`min_length=1` 认为没问题。但在业务上它和空字符串没区别。

规则引擎只能做机械判断（长度、大小、格式），做不了「这算不算空」这种语义判断。要自己写：

```python
from pydantic import BaseModel, Field, field_validator

class AnswerV5(BaseModel):
    answer: str = Field(min_length=1)

    @field_validator("answer")
    @classmethod
    def _not_blank(cls, v: str) -> str:
        if not v.strip():
            raise ValueError("answer 不能是空白字符串")
        return v.strip()
```

```python
print(repr(AnswerV5(answer="  hi  ").answer))
```

```text
'hi'
```

失败时：

```text
1 validation error for AnswerV5
answer
  Value error, answer 不能是空白字符串 [type=value_error, input_value='   ', input_type=str]
```

注意 `[type=value_error]`：这表示"你自己抛的 `ValueError`"，和 `string_too_short`（框架内置规则）区分开了。以后看日志一眼就知道是内置规则拦的还是你写的逻辑拦的。

### 逐块拆开讲

**① `@field_validator("answer")` 是什么**

它是一个**装饰器**。装饰器的本质：**把一个函数传给另一个函数，换一个新的回来。**

```python
@deco
def f(): ...

# 完全等价于
def f(): ...
f = deco(f)
```

`@` 只是语法糖，省掉最后那行重新赋值。`field_validator("answer")` 的意思是"这个函数负责校验 `answer` 字段"，Pydantic 在校验 `answer` 时会调用它。

（装饰器在 W2 第 03 节还会专门讲，那时我们自己写一个 `@retry`。这里先会用。）

**② 为什么必须 `@classmethod` 和 `cls`**

Pydantic 规定校验函数是**类级别**的工具，不属于某个具体对象。所以第一个参数是 `cls`（类本身），不是 `self`（对象）。`@classmethod` 是 Python 的写法约定，不加它会报错。

**③ 参数 `v` 和返回值**

- `v` 是**已经通过前面校验**的值。这里 `answer` 是 `str`、长度 ≥1，`v` 一定是字符串。
- **返回值才是最终存进去的值。** 你 `return v.strip()`，存的就是去掉首尾空格的版本；你 `return v`，空格就留着。
- 抛 `ValueError` 表示校验失败。

**④ 顺序陷阱（实测）**

```python
class C(BaseModel):
    low: int
    high: int

    @field_validator("high")
    @classmethod
    def _f(cls, v, info):
        print(info.data)
        return v

C(low=1, high=2)
```

输出：

```text
{'low': 1}
```

`info.data` 里**只有排在它前面、已经校验完的字段**。看不到 `high` 自己（还在校验中），也看不到后面定义的字段。

所以：**需要跨字段判断时，单字段校验器做不到**——这就是下一节。

**检查点 5**：把 `return v.strip()` 改成 `return v`，`AnswerV5(answer="  hi  ")` 打印出来是什么？

## 7. 第 6 版：`model_validator` —— 跨字段的规则

我们的业务里有两条规则，天生跨字段：

1. **拒答时不该附带引用**（都拒答了，引什么？）
2. **拒答时 confidence 不该很高**（没把握才拒答，怎么会 0.9）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  1

这两条同时看 `status`、`citations`、`confidence`，`field_validator` 做不了。用 `model_validator`：

```python
from typing import Literal
from pydantic import BaseModel, Field, model_validator

class AnswerV6(BaseModel):
    answer: str = Field(min_length=  1)
    citations: list[str] = []
    confidence: float = Field(ge=0.0, le=1.0)
    status: Literal["ok", "refused"] = "ok"

    @model_validator(mode="after")
    def _refused_rule(self) -> "AnswerV6":
        if self.status == "refused" and self.citations:
            raise ValueError("拒答时不应该附带引用")
        if self.status == "refused" and self.confidence > 0.5:
            raise ValueError("拒答说明没把握，confidence 不该这么高")
        return self
```

几个新语法：

| 语法                         | 含义                                       |
| -------------------------- | ---------------------------------------- |
| `Literal["ok", "refused"]` | 只能取这两个值之一，其他一律报错。比 `str` 精确，也不用你自己写检查    |
| `mode="after"`             | **所有字段都校验完、对象已经建好**，我才来判                 |
| `self.status`              | 因为是 after 模式，`self` 上的字段都是最终值，随便读，没有顺序问题 |
| `-> "AnswerV6"`            | 字符串形式的前向引用（类还没写完，只能写字符串）                 |

跑失败：

```python
AnswerV6(answer="资料里没有", citations=["km-03"], confidence=0.2, status="refused")
```

```text
1 validation error for AnswerV6
  Value error, 拒答时不应该附带引用 [type=value_error, input_value={'answer': '资料里没有'...}, input_type=dict]
```

**注意一个细节**：这次报错**没有字段名那一行**，只有 `Value error, ...`。因为跨字段的规则不属于任何一个字段，Pydantic 指不出该怪谁。这是 `model_validator` 的代价——所以它的报错文案必须写得足够清楚。

**检查点 6**：`status` 用的是默认值 `"ok"` 时，`_refused_rule` 还会运行吗？

> 会。`model_validator(mode="after")` 每次构造对象都跑，跟字段是不是默认值无关。这一点和 `field_validator` 正好相反（后者对默认值不运行，见第 6 节）。

## 8. 第 7 版：`extra` —— 模型偷偷多给了字段

前六版都在管"你给的值对不对"。这一版换个方向：**如果模型给你一个你压根没定义的字段，你怎么知道？**

先看现象。模型"话多"的时候，会多塞 `mood`、`思考过程`、`notes` 这类字段：

```python
raw = {"answer": "K 需预先指定", "confidence": 0.8,
       "mood": "confident", "思考过程": "先看资料"}

a = AnswerV6(**raw)
print(a)
print(a.model_dump())
```

实测输出：

```text
answer='K 需预先指定' citations=[] confidence=0.8 status='ok'
{'answer': 'K 需预先指定', 'citations': [], 'confidence': 0.8, 'status': 'ok'}
```

四个键进来，四个已知字段留下，**另外两个凭空消失**：不报错、不警告，`model_dump()` 里也找不到。

### 为什么这是问题

你从此失去了一个信号：**模型到底有没有按你的格式走。**

- 多一个 `mood` → 说明它在自由发挥，下一次就可能把 `answer` 写成 `Answer`
- 多一个 `思考过程` → 说明它把你的输出要求当成了聊天，正文里也可能混着"好的，以下是"

这两件事都不致命，但都是**早期预警**。默认配置把报警器静音了。

### 打开它：`model_config = ConfigDict(extra="forbid")`

```python
from pydantic import BaseModel, ConfigDict

class AnswerV7(BaseModel):
    model_config = ConfigDict(extra="forbid")   # 多余字段 → 报错

    answer: str
    confidence: float

AnswerV7(answer="x", confidence=0.5, 为什么="补充")
```

```text
1 validation error for AnswerV7
为什么
  Extra inputs are not permitted [type=extra_forbidden, input_value='补充', input_type=str]
```

三个取值：

| 值                  | 多出来的字段      | 什么时候用             |
| ------------------ | ----------- | ----------------- |
| `"ignore"`（默认）     | 静默丢掉        | 内部数据，源头可信         |
| `"forbid"`         | **报错**      | ← LLM 场景选这个       |
| `"allow"`          | 保留，能访问      | 几乎不用；等于放弃形状       |

`[type=extra_forbidden]` 这个机器码要记住：写测试断言时用它，比匹配中文报错文案稳（文案随版本变，`type` 不变）。

### 为什么写在 `model_config` 而不是 `Field`

| 你想管的                                | 写在哪                        |
| ----------------------------------- | -------------------------- |
| **某个字段**的长度、范围、默认值                  | `Field(...)` 挂在那一个字段上      |
| **整个类**的行为（多余字段怎么办、字符串要不要自动 strip）   | `model_config = ConfigDict(...)` |

`extra` 管的是"这个类收不收额外字段"，不是某个字段的属性。

**一个陷阱**：写成 `Field(extra="forbid")` 也**不会报错**，Pydantic 只是给你一条 `DeprecationWarning`，然后把它当 `json_schema_extra` 收下——**规则根本没生效**，字段照旧被静默丢弃。我实测过：

```text
PydanticDeprecatedSince20: Using extra keyword arguments on `Field` is deprecated ...
```

所以看到"没报错但也没生效"，第一件事是确认这行配置写在哪。

**检查点 7**：开了 `forbid` 之后，模型偶尔多返回一个 `"reason"` 字段，你的程序会怎样？这是好事还是坏事？

> 这次请求直接 `ValidationError`。**是好事**——它在告诉你"模型没照格式走"，比三个月后才发现某个字段一直是错的要好。前提是你有重试或降级（第 10 节讲）。

## 9. 第 8 版：从文本到对象，还差两步

前面七版都建立在一个假设上：**我已经有一个 dict 了。**

可模型给的是文本，还带围栏和废话（第 1 节那段）。所以完整的链路是四段：

```text
① 模型原始文本  --抠-->  ② 纯 JSON 文本  --json.loads-->  ③ dict  --model_validate-->  ④ Answer 对象
```

四段，三个失败点：

| 位置     | 什么时候失败                   | 抛什么                 |
| ------ | ------------------------ | ------------------- |
| ①→② 抠  | 输出里压根没有一个 `{...}`        | `ValueError`（我们自己抛） |
| ②→③ 解析 | 有 JSON 但语法坏了（少逗号、用了中文引号） | `JSONDecodeError`   |
| ③→④ 校验 | JSON 合法，但字段/类型/范围不对      | `ValidationError`   |

抠的那一步要同时应付两种脏：**套了围栏的**和**没围栏但前后有废话的**。

````python
import re

FENCE = re.compile(r"```(?:json)?\s*(.*?)```", re.S)

def extract_json(raw: str) -> str:
    m = FENCE.search(raw)
    if m:
        return m.group(1).strip()
    start, end = raw.find("{"), raw.rfind("}")
    if start == -1 or end <= start:
        raise ValueError("输出里没有 JSON 对象")
    return raw[start:end + 1]
````

### 正则逐字符拆解

`r"```(?:json)?\s*(.*?)```"` 拆成七段：

| 片段          | 含义                                                         |
| ----------- | ---------------------------------------------------------- |
| `r"..."`    | **原始字符串**，里面的 `\` 不当转义符。正则里反斜杠多，必须用 r                      |
| ` ``` `     | 三个反引号，字面量（围栏本身）                                            |
| `(?:json)?` | 一个**非捕获组**。`?:` = 只分组不单独取出；`?` = 可有可无。即围栏后可能跟 `json`，也可能不跟 |
| `\s*`       | 任意空白字符（空格、换行、制表符）重复 0 次以上                                  |
| `(.*?)`     | **捕获组**，我们要的内容。`.` = 任意字符，`*` = 重复任意次，`?` = 非贪婪（能少匹配就少匹配）  |
| ` ``` `     | 结束的围栏                                                      |
| `re.S`      | 让 `.` 也能匹配换行符。**不加这个，JSON 里的换行会把匹配断掉**                     |

两个新语法点：

- `m := FENCE.search(raw)` —— 海象运算符，赋值的同时判断真假。等价于先 `m = ...` 再 `if m is not None`。
- `m.group(1)` —— 取第 1 个捕获组，也就是 `(.*?)` 抓到的内容。

### 兜底逻辑

没有围栏时（比如模型直接甩一段 JSON），用 `find("{")` 找第一个左花括号，`rfind("}")` 找**最后一个**右花括号，中间全要。

为什么不用 `find("}")`？因为 JSON 里可能有嵌套：`{"a": {"b": 1}}`，第一个 `}` 是内层的。`rfind` 找最后一个才对。

### 组装

```python
def parse_answer(raw: str) -> Answer:
    try:
        data = json.loads(extract_json(raw))
    except json.JSONDecodeError as e:
        raise ValueError(f"不是合法 JSON: {e}") from e
    if not isinstance(data, dict):
        raise ValueError(f"顶层必须是对象，拿到 {type(data).__name__}")
    return Answer.model_validate(data)
```

三个细节：

1. `raise ... from e` 是**异常链**：把原始异常挂在新的上面，追溯时两层都能看到。
2. `isinstance(data, dict)` 检查顶层类型：模型可能返回 `[1,2,3]` 这种数组，得挡掉。
3. **`model_validate(data)` 而不是 `Answer(**data)`**。区别：
   - `**data` 是"把 dict 拆成关键字参数"，键名必须是合法 Python 标识符
   - `model_validate` 接收整个 dict，语义就是"用这份数据校验我的模型"，也是 FastAPI、LangChain 内部统一用的入口

跑一下：

````python
print(parse_answer('```json\n{"answer": "x", "confidence": "0.8"}\n```'))
````

```text

```

## 10. 第 9 版：重试 —— 一次失败就崩是不合格的

到这里，解析失败仍然会直接抛异常。生产的做法是：**拿着"你上次输出不合法，请只输出 JSON"的提示再问一次**，把几次输出依次试。

```python
from collections.abc import Iterable

class LLMParseError(RuntimeError):
    """所有候选输出都解析失败。调用方应该降级或重问，而不是崩。"""

def parse_with_retry(candidates: Iterable[str]) -> Answer:
    errors = []
    for i, raw in enumerate(candidates, 1):
        try:
            return parse_answer(raw)
        except ValueError as e:
            errors.append(f"第 {i} 次: {e}")
    raise LLMParseError("；".join(errors) or "没有任何候选输出")
```

跑：

```python
bad = '{"answer": "", "confidence": 2}'
good = '{"answer": "K 要预先指定", "confidence": 0.8}'
print(parse_with_retry([bad, "随便说说", good]))
```

```text
answer='K 要预先指定' citations=[] confidence=0.8 status='ok'
```

### 两个设计决定，值得记住

**① 入参是"候选列表"，不是"模型客户端"**

```python
def parse_with_retry(candidates):        # ✅ 能离线测
def parse_with_retry(llm_client, prompt): # ❌ 每次测试都要联网、花钱、还不稳定
```

这个函数不知道"重试"的候选从哪来，它只负责"依次试"。真正的调用方在外面用循环生成候选。这叫**依赖注入**的朴素版本，好处是**测试里不用联网**——W3 讲并发时会大量用到这个思路。

**② 全失败抛自定义异常 `LLMParseError`**

为什么不用 `ValueError` 一路抛上去？因为调用方需要**区分**：

| 异常                 | 调用方该做什么                |
| ------------------ | ---------------------- |
| `LLMParseError`    | 模型不听话 → 返回兜底话术、或提示用户重试 |
| `ValueError`（不认识的） | 代码有 bug → 报警、别吞掉       |

自定义异常就是给调用方一个明确的"这是可预期的失败，按预案处理"的信号。`RuntimeError` 作为基类表示"运行时才可能出现的问题"。

### 异常家族关系（这决定了 `except` 怎么写）

实测：

```python
issubclass(ValidationError, ValueError)        # True
issubclass(json.JSONDecodeError, ValueError)   # True
```

`ValidationError` 和 `JSONDecodeError` **都是 `ValueError` 的子类**。所以 `except ValueError` 一个就够了，写 `except (ValueError, ValidationError)` 是多余的。

> 这也是个通用技巧：写 `except` 之前先想清楚"这几个异常是不是同一家族"，能少写就别多写。

**检查点 9**：如果三次候选全失败，`parse_with_retry` 抛出的异常信息里，能看出每一次分别错在哪吗？

## 11. 最终文件（完整，可直接存成 `schema.py`）

前面九版拼起来就是它。这份代码可以直接抄进 `w02/schema.py` 覆盖原文件，或单独存一个文件跑。

````python
"""W2 第一讲：类型注解 + Pydantic —— 给 LLM 的输出上锁。

为什么 LLM 应用第一件事是干这个：
模型返回的是**字符串**，你的程序要的是**结构体**。中间这道校验层没了，
后面所有代码都在猜字段在不在、类型对不对、值合不合法。
"""

from __future__ import annotations

import json
import re
from collections.abc import Iterable
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, field_validator, model_validator

FENCE = re.compile(r"```(?:json)?\s*(.*?)```", re.S)


class LLMParseError(RuntimeError):
    """所有候选输出都解析失败。调用方应该降级或重问，而不是崩。"""


class Citation(BaseModel):
    doc_id: str = Field(min_length=1, description="文档标识")
    quote: str = Field(min_length=1, max_length=500, description="原文引用片段")


class Answer(BaseModel):
    """RAG 生成层的输出契约。以后所有 prompt 都必须按这个 schema 产出。"""

    model_config = ConfigDict(extra="forbid")

    answer: str = Field(min_length=1, description="给用户的回答")
    citations: list[Citation] = Field(default_factory=list, max_length=5)
    confidence: float = Field(ge=0.0, le=1.0)
    status: Literal["ok", "refused"] = "ok"

    @field_validator("answer")
    @classmethod
    def _not_blank(cls, v: str) -> str:
        if not v.strip():
            raise ValueError("answer 不能是空白字符串")
        return v.strip()

    @model_validator(mode="after")
    def _refused_rule(self) -> Answer:
        """跨字段规则只能写在 model_validator 里 —— field_validator 看不到后面的字段。"""
        if self.status == "refused" and self.citations:
            raise ValueError("拒答时不应该附带引用")
        if self.status == "refused" and self.confidence > 0.5:
            raise ValueError("拒答说明没把握，confidence 不该这么高")
        return self


def _extract_json(raw: str) -> str:
    """模型爱加围栏、爱在 JSON 前后写废话，这里把裸 JSON 抠出来。"""
    if m := FENCE.search(raw):
        return m.group(1).strip()
    start, end = raw.find("{"), raw.rfind("}")
    if start == -1 or end <= start:
        raise ValueError("输出里没有 JSON 对象")
    return raw[start : end + 1]


def parse_answer(raw: str) -> Answer:
    """单次解析：抽 JSON → json.loads → Pydantic 校验。任一步失败都抛异常。"""
    try:
        data = json.loads(_extract_json(raw))
    except json.JSONDecodeError as e:
        raise ValueError(f"不是合法 JSON: {e}") from e
    if not isinstance(data, dict):
        raise ValueError(f"顶层必须是对象，拿到 {type(data).__name__}")
    return Answer.model_validate(data)


def parse_with_retry(candidates: Iterable[str]) -> Answer:
    """把模型的多轮输出依次试一遍 —— 这就是「解析失败重试」的最小实现。

    真实场景里 candidates 来自「重问一次」，这里用可迭代对象让逻辑可测。
    """
    errors: list[str] = []
    for i, raw in enumerate(candidates, 1):
        try:
            return parse_answer(raw)
        except ValueError as e:  # ValidationError 本身就是 ValueError 子类，不用重复捕获
            errors.append(f"第 {i} 次: {e}")
    raise LLMParseError("；".join(errors) or "没有任何候选输出")


if __name__ == "__main__":
    good = '{"answer": "K-means 的 K 要手动定", "citations": [{"doc_id": "d1", "quote": "K 需预设"}], "confidence": 0.8}'
    bad = '好的，以下是结果：\n```json\n{"answer": "", "confidence": 2}\n```'
    print(parse_with_retry([bad, good]).model_dump_json(indent=2))
````

`from __future__ import annotations` 这一行前面没讲，补一句：它让**所有注解变成字符串**（延迟求值），这样 `def _refused_rule(self) -> Answer` 里的 `Answer` 即使类还没写完也不会报 `NameError`。不加也能跑（Pydantic 内部会处理），但加上更稳，也是现在 Python 项目的默认写法。

最后那个 `if __name__ == "__main__":` 块是**自测入口**，不是库的一部分：`python -m w02.schema` 会拿一段"带围栏 + answer 为空 + confidence=2"的坏输出和一段好输出喂给 `parse_with_retry`，打印出解析成功的 JSON。而 `pytest` 导入这个模块时 `__name__` 不等于 `"__main__"`，这一块不会执行——测试输出里就不会混进这段 JSON。

## 12. 测试：证明它真的能用

测试不是"证明代码对"，是**把每个失败场景钉死**，以后改代码时它替你守着。

````python
from __future__ import annotations

import pytest
from pydantic import ValidationError

from w02.schema import LLMParseError, parse_answer, parse_with_retry

GOOD = (
    '{"answer": "混合检索能提升召回", '
    '"citations": [{"doc_id": "d1", "quote": "BM25 补充向量召回"}], '
    '"confidence": 0.82}'
)


def test_正常解析():
    a = parse_answer(GOOD)
    assert a.confidence == pytest.approx(0.82)
    assert a.citations[0].doc_id == "d1"


def test_带_markdown_围栏():
    assert parse_answer(f"```json\n{GOOD}\n```").answer == "混合检索能提升召回"


def test_前后有废话():
    raw = f"好的，结果如下：\n{GOOD}\n希望对你有帮助。"
    assert parse_answer(raw).answer == "混合检索能提升召回"


def test_缺字段报错():
    with pytest.raises(ValidationError):
        parse_answer('{"confidence": 0.5}')

    with pytest.raises(ValidationError):
        parse_answer('{"answer": "x", "confidence": 1.5}')


def test_answer_全是空白():
    with pytest.raises(ValidationError):
        parse_answer('{"answer": "   ", "confidence": 0.5}')


def test_多余字段报错():
    with pytest.raises(ValidationError, match="extra_forbidden"):
        parse_answer('{"answer": "x", "confidence": 0.5, "理由": "我自己加的"}')


def test_拒答却带引用():
    with pytest.raises(ValidationError, match="不应该附带引用"):
        parse_answer(
            '{"answer": "资料里没有", "confidence": 0.2, "status": "refused",'
            ' "citations": [{"doc_id": "d1", "quote": "q"}]}'
        )


def test_重试取第一个成功的():
    bad = '{"answer": "", "confidence": 2}'
    assert parse_with_retry([bad, "随便说说", GOOD]).confidence == pytest.approx(0.82)


def test_全部失败抛_LLMParseError():
    with pytest.raises(LLMParseError):
        parse_with_retry(['{"answer": ""}', "not json"])
````

### 测试的四个构件

| 构件                               | 作用                            |
| -------------------------------- | ----------------------------- |
| `def test_xxx():`                | 函数名必须以 `test_` 开头，pytest 自动发现 |

| `pytest.raises(..., match="文字")` | 进一步要求异常信息里包含这段文字              |
| `pytest.approx(0.82)`            | 浮点数别用 `==` 比，会有精度误差，用 approx  |

<summary>答案（先自己想，别点开）</summary>

## 14. 一页速查表

| 你要做的事          | 写法                                                |
| -------------- | ------------------------------------------------- |
| 定义结构           | `class X(BaseModel):`                             |
| 加约束            | `Field(min_length=1, ge=0, le=1)`                 |
| 给默认值           | `= 0.5`；列表/字典用 `default_factory=list`             |
| 加说明（会给模型看）     | `Field(description="...")`                        |
| 只允许几个值         | `Literal["ok", "refused"]`                        |
| 单字段自定义校验       | `@field_validator("字段名")` + `@classmethod`        |
| 跨字段校验          | `@model_validator(mode="after")`，最后 `return self` |
| 禁止多余字段         | `model_config = ConfigDict(extra="forbid")`       |
| 从 dict 建对象     | `X.model_validate(data)`                          |
| 导出 JSON Schema | `X.model_json_schema()`                           |
| 导出 JSON 字符串    | `X.model_dump_json()`                             |
| 导出 dict        | `X.model_dump()`                                  |
