# W2 · Python 工程化

计划里 W2 的原文要求：**类型注解、Pydantic、异常与重试、装饰器、生成器、上下文管理器、logging、pytest**，产出是「一个带完整类型与测试的工具库」。

八个知识点塞一周太挤，而且它们不是并列关系——装饰器是为了包住重试，pytest 是为了验收前面所有东西。所以拆成 6 节，每节一个主题、一个可跑产出、一条验收。

| 节 | 主题 | 解决的具体痛点 | 产出 | 预计 | 状态 |
|---|---|---|---|---|---|
| **01** | 类型注解 + Pydantic | 模型返回的是字符串，程序要的是对象 | `schema.py` + 15 用例 | 2.5h | ✅ 已讲 |
| **02** | 异常体系与重试 | LLM 调用超时/429/5xx 是常态，10% 会失败 | `errors.py` + 23 用例 | 1.5h | ✅ 已讲 |
| **03** | 装饰器 | 重试、计时、日志不能每个函数抄一遍 | `decorators.py`（`@retry` + `@timed`）+ 12 用例 | 2h | ✅ 已讲 |
| **04** | 生成器 + 上下文管理器 | 流式输出要一段一段吐；连接/文件必须保证关 | `streaming.py`（流式切分）+ `spans.py`（`with` 资源管理）+ 25 用例 | 2h | ✅ 已讲 |

## 每份讲义的统一结构（2026-10-29 起强制）

之前两份讲义都是"打开就直接进正文"，缺前置，所以读起来像突然冒概念。现在固定六段，顺序不可调：

| 段 | 内容 | 为什么必须有 |
|---|---|---|
| 0.1 本节目标 | 学完你能做什么 + 判断标准 + 产出 + 时长 | 先给终点，读的时候知道往哪看 |
| 0.2 前置知识 | 本节假设你会的东西，每条配 3–5 行**就地补救** | 不许出现"答不上回去翻上一份文档" |
| 0.3 概念地图 | 本节所有新术语：定义 + 生活类比 + 出现在第几节 | 术语在首现之前先登记，正文不再突然冒词 |
| 0.4 知识衔接 | 上一节解决什么 → 遗留什么 → 本节补什么 → 交给谁 | 让每一节都有来处和去处 |
| 正文 | 原来的逐版演进 / 踩坑过程 | 不动 |
| 收口 | 检查点 + 速查 + 下一节预告 | 能自测才算学完 |

配套纪律：文中任何"这段代码会报什么错"的断言，必须是真跑出来的（未实测要标注）；表格第一次出现前必须先有一句话说明它在回答什么问题。

## 为什么 01 排第一

因为它定的是**后面所有代码的输入输出形状**：

- W5 结构化输出：同一套 `BaseModel` 直接当 JSON Schema 喂给模型
- W4 FastAPI：请求体和响应体就是 `BaseModel`，校验和文档自动生成
- W12 tool calling：工具的入参就是 `BaseModel`

先有契约，后面才有得谈。所以这一节虽然只占 W2 的 1/5，但它是 W2 里唯一一个「必须彻底懂」的。

## 每节的验收方式

不是「看完了」，是三条都得过：

1. 能不看讲义把这段代码重写出来
2. `pytest` 全绿，且能解释每个用例在防什么
3. 能对着屏幕讲 3 分钟：这段解决什么问题、不这么写会怎么坏
