## 1. 前置知识：五个概念，缺一个都读不下去

这一节的所有代码都可以直接粘进 `python -c` 或存成任意 `.py` 跑，不依赖本项目任何文件。

### 1.1 函数是对象

**定义**：Python 里 `def` 干的事只有两件——造一个函数对象，把名字绑上去。所以函数和整数、字符串一样是值：能赋值给变量、能当参数传、能当返回值。

```python
def greet(name):
    """打招呼。"""
    return f"hi {name}"

alias = greet                      # 不加括号 = 传对象本身
print(type(greet).__name__, alias is greet)
print(repr(alias))
print(repr(alias("Tom")))
```

实测输出：

```text
function True
<function greet at 0x000002380B1EA3E0>
'hi Tom'
```

（那个 `0x...` 是内存地址，每次运行都变，正常。）

**这个例子为什么在这里出现**：装饰器的本质就是把函数当参数传进另一个函数。如果你还觉得"函数是代码、不是东西"，后面所有代码都会看不懂。

**最容易混的一处**：`greet` 和 `greet()` 是两回事。

| 写法             | 含义      | 类型         |
| -------------- | ------- | ---------- |
| `greet`        | 函数对象本身  | `function` |
| `greet("Tom")` | 执行它，返回值 | `str`      |

装饰器**全程只碰左边这种**。`@retry` 递给 `retry` 的是 `fetch` 这个对象，不是 `fetch()` 的结果。

**这个类比在哪里失效**：把函数当"东西"传，很像把一把钥匙交给别人。但钥匙交出去就只剩一把，函数交出去是**又多了一个引用**——原名字照样能用。上一节实测里 `greet("tom")` 在包装之后仍然返回 `'hi tom'`，就是这个意思。

### 1.2 闭包

**定义**：内层函数被返回之后，仍然记得外层函数的变量。

```python
def make_multiplier(n):
    def inner(x):
        return x * n
    return inner

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(5), triple(5))
print(double.__closure__[0].cell_contents)
```

实测输出：

```text
10 15
2
```

**逐行看**：

- `make_multiplier(2)` 执行完，函数就已经返回了，`n` 这个局部变量照理该消失。
- 但 `inner` 被返回出去了，而 `inner` 的函数体里用到了 `n`，于是 Python 把 `n` **打包进 `inner` 的 `__closure__` 里一起带走**。
- `double.__closure__[0].cell_contents` 读出来的就是那个 `2`。

**这个例子为什么在这里出现**：装饰器的 `wrapper` 要用到外层的 `max_attempts`、`sleep`、`func` 这些变量。它能用到，靠的就是闭包。没有闭包，装饰器传参这件事根本无从谈起。

**这个类比在哪里失效**：常说闭包像"出门前把钥匙塞进口袋"。但口袋里的钥匙是**拷贝**——你手里还有一把；闭包里的变量是**同一个对象**，不是拷贝。比如外层有个列表，内层往里 `append`，外层能看见变化。

### 1.3 `*args` 与 `**kwargs`

**定义**：`*args` 收下所有多余的位置参数（变成一个 tuple），`**kwargs` 收下所有多余的关键字参数（变成一个 dict）。调用时 `fn(*args, **kwargs)` 再原样摊开传进去。

```python
def show(*args, **kwargs):
    print("args =", args)
    print("kwargs =", kwargs)

show(1, 2, 3, name="Tom", age=18)
```

实测输出：

```text
args = (1, 2, 3)
kwargs = {'name': 'Tom', 'age': 18}
```

**这个例子为什么在这里出现**：装饰器写的时候**还不知道将来要包哪个函数**——那个函数可能有 0 个参数，也可能有 5 个。所以 wrapper 只能用"什么都收、原样转交"的写法。

**必须记住的边界**：`*args/**kwargs` 透传的**只是值，不是名字**。wrapper 收到的是"位置 0 是 1、位置 1 是 2"，至于这些参数原本叫 `a`、`b` 还是 `text`，它不知道。§4.2 要讲的 pytest 事故，根子就在这句话上。

### 1.4 函数的三样元信息

**定义**：函数对象身上挂着 `__name__`（名字）、`__doc__`（文档字符串）、以及一份**签名**（有哪些参数、有没有默认值、注解是什么）。签名可以用标准库 `inspect.signature()` 读出来。

```python
from __future__ import annotations

import inspect


def original(text: str, limit: int = 10) -> str:
    """把 text 重复 limit 次。"""
    return text * limit


print(original.__name__)
print(repr(original.__doc__))
print(inspect.signature(original))
```

实测输出（注意注解带引号）：

```text
original
'把 text 重复 limit 次。'
(text: 'str', limit: 'int' = 10) -> 'str'
```

引号来自第一行 `from __future__ import annotations`——它让所有注解**延迟成字符串**，不再当场求值。这是现在 Python 项目的默认写法，作用是：即使某个类型还没定义好，也不会报 `NameError`。

把那一行删掉再跑，输出会变（同样实测）：

```text
(text: str, limit: int = 10) -> str
```

两种写法功能相同，`decorators.py` 用的是带 `from __future__` 的那种，所以本节后面出现的签名都带引号。

**这个例子为什么在这里出现**：所有工具都靠这三样东西认人——

| 谁        | 靠什么认              | 认错了会怎样                   |
| -------- | ----------------- | ------------------------ |
| pytest   | 签名，决定注入哪些 fixture | 报"缺参数"，§4.2 实测           |
| 日志       | `__name__`        | 日志里写着 `wrapper`，不知道是哪个函数 |
| IDE / 帮助 | `__doc__`         | 悬停看不到文档                  |
| 调试器      | `__name__`        | 断点堆栈全是 `wrapper`         |

**这个类比在哪里失效**：元信息像身份证，但身份证被涂改是违法的；`__name__` 可以被随意改，没有任何检查。`functools.wraps` 干的就是"照着原身份证重抄一张"。

### 1.5 `functools` 是什么

**定义**：`functools` 是 Python 标准库里的一个模块，名字是 "function tools"（函数工具）的缩写，读音大约是"放克-图尔斯"。里面装的是处理函数的小工具，本节只用一个：`functools.wraps`。

**为什么在这里出现**：它是 §4.3 用来修复元信息的现成装饰器。**装饰器的第一个真实用例，就是用它来写装饰器。**

它自己的用法是 `@functools.wraps(func)` 贴在 wrapper 上，作用是把 `func` 的 `__name__`、`__doc__`、`__module__`、`__qualname__`、`__dict__` 复制给 wrapper，并额外设一个 `__wrapped__` 属性指回 `func`。

`__wrapped__` 这个属性是 §4.3 的关键，先记住名字。

## 3. 知识衔接：为什么 02 学完必须学 03

因果链是这样的，一步推一步：

1. **01 解决了**"模型返回的 JSON 靠不靠得住"——用 Pydantic 在边界上校验。
2. **02 解决了**"调用失败要不要重试"——`classify()` 把异常分成两类，`retry_call()` 给能重试的那类套上退避重试。
3. **02 遗留了一个问题**：`retry_call` 的签名是 `retry_call(fn: Callable[[], T], ...)`——它收的是**无参函数**。而你真正要调的那个调用是带参数的：
   > `retry_call(lambda: client.chat.completions.create(model="gpt-4o-mini", messages=[...]))`
   （这一行是示意，`client` 是 02 里那个已经建好的 SDK 客户端，本节不需要它。）

   每处调用点都得现场造一个 `lambda` 把参数裹进去。项目里 20 个调用点，就有 20 个这样的 `lambda`，而且每个 `lambda` 里的参数列表都要跟真实函数保持一致（改一个参数名要改两处）。
4. **03 补的就是这一层**：让"重试"变成贴在函数头上的一个标签，参数照常写在函数签名里，不再需要 `lambda`。

   注意因果关系——**不是"装饰器很酷所以学装饰器"，是"02 的重试函数用起来别扭，所以需要装饰器"**。这也是为什么本节 `decorators.py` 里一行重试逻辑都没重写：它只是换个入口去调 02 的 `retry_call`。
5. **结果交给 04**：04 讲生成器与上下文管理器。那时你会发现，装饰器、`with`、`yield` 是同一套思路的三种形态——**把"每次都一样的骨架"抽出来，把"每次不一样的那部分"留给你填**。

一句话概括：**02 把重试逻辑抽成了函数；03 把"调用函数这个动作"也抽走了。**

## 4. 核心内容

### 4.1 从头开始：v1 手写包装，不带任何语法糖

不从 `@` 讲起，先看它背后那件事。

目标：让 `fetch_summary` 在失败时自动重试，同时**函数体里一行重试代码都不写**。

```python
import inspect
from w02.errors import retry_call


def retry(fn):
    def wrapper(*args, **kwargs):
        return retry_call(lambda: fn(*args, **kwargs), sleep=lambda s: None)
    return wrapper


calls = []


@retry
def fetch_summary(text: str) -> str:
    """调模型写摘要。"""
    calls.append(text)
    if len(calls) < 3:
        raise TimeoutError("mock timeout")
    return f"摘要：{text}"


print("返回:", fetch_summary("原文"))
print("调用次数:", len(calls))
print("__name__ :", fetch_summary.__name__)
print("__doc__  :", repr(fetch_summary.__doc__))
print("signature:", inspect.signature(fetch_summary))
```

在项目根目录跑（`from w02.errors import` 要求工作目录是项目根）：把它存成 `w02/try03.py`，然后 `python -m w02.try03`。

实测输出：

```text
返回: 摘要：原文
调用次数: 3
__name__ : wrapper
__doc__  : None
signature: (*args, **kwargs)
```

**前两行说明功能是对的**：前两次抛 `TimeoutError`，第 3 次成功，一共调了 3 次。**后三行是 v1 的病**，§4.2 细说。

逐行看这 12 行：

| 行 | 代码                                             | 作用                                                          | 删掉会怎样                                       |
| - | ---------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------- |
| 1 | `def retry(fn):`                               | 接收**函数对象**。注意参数名是 `fn`，不是 `fn()`                            | 没有入口，装饰器不成立                                 |
| 2 | `def wrapper(*args, **kwargs):`                | 定义"将来真正被调用的那个新函数"                                           | 没有东西可返回                                     |
| 3 | `retry_call(lambda: fn(*args, **kwargs), ...)` | 把 `fn` 和它的参数裹成一个无参 lambda，交给 02 的重试环                        | `retry_call` 只收无参函数，直接传 `fn` 会报 `TypeError` |
| 4 | `sleep=lambda s: None`                         | 让重试**不真睡**，这 12 行才跑得快                                       | 实测会真睡 0.6 + 1.09 秒                          |
| 5 | `return wrapper`                               | 把新函数交出去                                                     | 装饰器返回 `None`，`fetch_summary` 会变成 `None`     |
| 6 | `@retry`                                       | **语法糖**，等价于函数定义完之后执行 `fetch_summary = retry(fetch_summary)` | —                                           |

第 6 行是本节唯一的新语法，但它是纯语法糖：**`@` 不产生任何新能力，它只是把"定义完再赋值"这一句提前写到了函数头上。**

机械地展开一遍，两个版本其实完全相同（下面只是语法对照，`retry` 用的是上一段那个，不能单独跑）：

```python
# 写法 A（用 @）
@retry
def f(text): ...

# 写法 B（不用 @，等价）
def f(text): ...
f = retry(f)
```

实测这两种写法 + `@retry()` + `retry(f)` 直接调用，四种都能工作：

```text
a -> A      # @retry
b -> B      # @retry()
c -> C      # @retry(max_attempts=5)
d -> D      # d = retry(d)
```

**这个类比在哪里失效**：常说装饰器像"给手机套壳"。但壳只改变外观，装饰器**改变的是调用时的行为**——它可能让同一个函数被调 3 次。更准确的类比是"给函数配了个秘书"：你找的还是那个人，但秘书会先挡一道、记一笔、失败了再帮你约一次。


### 4.2 v1 的三个代价，每个都有实测

#### 代价一：函数的三样元信息全丢了

实测对比，同一个函数加不加 `@retry`：

|            | 未装饰                  | `@retry` 后          |
| ---------- | -------------------- | ------------------- |
| `__name__` | `fetch_summary`      | `wrapper`           |
| `__doc__`  | `"调模型写摘要。"`          | `None`              |
| 签名         | `(text: str) -> str` | `(*args, **kwargs)` |

后果：日志里会写 `wrapper 调用失败`，你根本不知道是哪个函数；`help()` 看不到文档；断点堆栈里一层层全是 `wrapper`。

#### 代价二：在 pytest 里会炸，而且炸得莫名其妙

这是本节最值钱的一条。同一个装饰器，一个不加 `functools.wraps`、一个加，包同一个需要 `tmp_path` fixture 的测试函数：

```python
import functools

from w02.errors import retry_call


def retry_plain(fn):
    def wrapper(*args, **kwargs):
        return retry_call(lambda: fn(*args, **kwargs), sleep=lambda s: None)
    return wrapper


def retry_wrapped(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        return retry_call(lambda: fn(*args, **kwargs), sleep=lambda s: None)
    return wrapper


@retry_plain
def test_没有wraps_要fixture(tmp_path):
    assert (tmp_path / "a.txt").parent.exists()


@retry_wrapped
def test_有wraps_要fixture(tmp_path):
    assert (tmp_path / "a.txt").parent.exists()
```

**先把 `tmp_path` 是什么说清楚**：它是 pytest 内置的 **fixture**（夹具）。fixture 是"测试开始前由 pytest 自动准备好、按参数名塞给你的东西"——`tmp_path` 塞给你一个本次测试专用的临时目录（一个 `pathlib.Path` 对象）。

关键在**靠参数名匹配**：你写 `def test_x(tmp_path)`，pytest 看到参数名叫 `tmp_path`，就去准备一个临时目录；参数名叫 `whatever`，它就找不到，报"不知道这是什么"。

这个"按参数名注入"的机制，正是下面这个坑的根子。

把它存成任意一个 `test_*.py`（本节实测时放在项目外的临时目录，用 `PYTHONPATH` 指回项目根），跑：

```text
.\.venv\Scripts\python.exe -m pytest test_wraps.py --color=no -o addopts="" -q --tb=line
```

实测输出：

```text
E   TypeError: test_没有wraps_要fixture() missing 1 required positional argument: 'tmp_path'

The above exception was the direct cause of the following exception:
E   w02.errors.FatalError: 未知异常，按不可重试处理：TypeError: test_没有wraps_要fixture() missing 1 required positional argument: 'tmp_path'

FAILED test_wraps.py::test_没有wraps_要fixture
1 failed, 1 passed in 0.04s
```

（耗时每次略有浮动，`0.04s` 附近。）

这段输出里有两层，值得分开看：

- **第一层 `TypeError`** —— 真正的病因，pytest 说的是"你少给我一个 `tmp_path`"。
- **第二层 `FatalError`** —— 02 的 `retry_call` 把这个 `TypeError` 当成"未知异常"翻译了一遍（`classify()` 的最后一个分支）。所以你在 `FAILED` 行看到的是 `FatalError`，`TypeError` 被藏在里面。
- 中间那句 `The above exception was the direct cause of the following exception` 就是 02 里 `raise err from exc` 的现场效果——原始异常挂在 `__cause__` 上，没丢。

**为什么报"缺参数"**：pytest 是**根据函数的签名**去找 fixture 的。它拿到的对象是 `wrapper`，签名是 `(*args, **kwargs)`——里面没有 `tmp_path` 这个词，于是它认定"这个测试不需要 fixture"，调用时一个参数都不给。wrapper 拿着空的 `args/kwargs` 去调原函数，原函数当场报缺参数。

这里有个反直觉的地方值得停一下：**参数明明写在你自己那个 `def test_xxx(tmp_path)` 里，报错却说缺参数。** 因为 pytest 看的是 wrapper 的签名，不是你的。你在 `def` 里写下的东西，被 wrapper 挡在门外了。

这个坑之所以难查，是因为它**不在装饰器里报错**，而是在你后来写的某个测试里报错，两者看着毫无关系。

#### 代价三：重试次数不能配

`@retry` 写死了 3 次、0.5 秒起步。想给某个函数配 5 次，只能再写一个 `retry5`。而 `@retry` 后面不能加括号——加了就变成"调用 `retry()`"，`fn` 没传，直接报 `TypeError: retry() missing 1 required positional argument: 'fn'`。

这三个代价对应三条独立的修法，下面逐个来。

### 4.3 v2：一行 `functools.wraps` 修好代价一

把 1.5 节的工具贴到 wrapper 上就行。下面这段接 §4.1 的代码，只多了一行 `import` 和一行装饰器，`retry_call` 的 import 沿用上面的：

```python
import functools


def retry(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        return retry_call(lambda: fn(*args, **kwargs), sleep=lambda s: None)
    return wrapper
```

只有第 1 行 `import` 和第 2 行装饰器是新增，其余一个字没改。

要看见效果，得有个能打印元信息的探针。下面这段**独立可跑**，不依赖前面的 `retry`：

```python
import functools
import inspect


def greet(name):
    """打招呼。"""
    return f"hi {name}"


def without_wraps(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper


def with_wraps(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper


for label, obj in (
    ("未装饰", greet),
    ("不加 wraps", without_wraps(greet)),
    ("加 wraps 后", with_wraps(greet)),
):
    print(f"{label:<10} | {obj.__name__:<8} | {inspect.signature(obj)} | {obj.__doc__!r}")
```

实测输出：

```text
未装饰        | greet    | (name) | '打招呼。'
不加 wraps   | wrapper  | (*args, **kwargs) | None
加 wraps 后  | greet    | (name) | '打招呼。'
```

|                  |    |                                                                                                    |
| ---------------- | -- | -------------------------------------------------------------------------------------------------- |
| 三列依次是 `__name__` | 签名 | `__doc__`。中间那一行就是"代价一"的现场：名字变了、签名塌成 `(*args, **kwargs)`、文档字符串丢了；第三行说明加一行 `@functools.wraps` 就全回来了。 |

**关键一点**：加了 wraps 之后，`inspect.signature(wrapper)` 显示 `(name)`，但 **wrapper 实际收的还是 `*args`**。它并不是真的变成了"只接一个叫 name 的参数"，只是**对外报告时照着原函数的样子报告**。

机制是 `functools.wraps` 在 wrapper 上设了 `__wrapped__ = fn`，而 `inspect.signature()` 的规则是"如果对象有 `__wrapped__`，就顺着它去找真正的签名"。

这解释了为什么 §4.2 那个 fixture 事故能修好：pytest 也走 `inspect.signature`，于是它看到了 `tmp_path`，就注入了。

**这个类比在哪里失效**：`__wrapped__` 像"身份证复印件"——pytest 之类的外部工具看复印件，就认对了；但如果某个工具直接读 `wrapper.__code__.co_varnames`（字节码层面的局部变量名），看到仍然是 `('args', 'kwargs')`。也就是说 wraps 是**对外**修好了，对内并没有变。

### 4.4 v3：装饰器工厂——修好代价三

想让 `@retry(max_attempts=5)` 成立，就得让 `retry` 在"还没看到函数"的时候先收下参数。办法是**再套一层函数**：

```python
def retry_factory(max_attempts=3):
    def decorator(fn):
        def wrapper(*args, **kwargs):
            return retry_call(
                lambda: fn(*args, **kwargs),
                max_attempts=max_attempts,
                sleep=lambda s: None,
            )
        return wrapper
    return decorator
```

三层函数，看着唬人，其实只是**三段时间上分开的执行**。`@retry_factory(max_attempts=5)` 这一行，Python 实际按这个顺序做：

| 步骤 | 发生什么                            | 收什么 | 还什么              |
| -- | ------------------------------- | --- | ---------------- |
| ①  | `retry_factory(max_attempts=5)` | 参数  | `decorator` 这个函数 |
| ②  | 把下面定义的函数传进去：`decorator(f)`      | `f` | `wrapper`        |
| ③  | 赋值：`f = wrapper`                | —   | —                |

实测第 ① ② 步的返回值：

```text
第 1 步 retry_factory(max_attempts=5) -> decorator
第 2 步 decorator(f) -> function
共尝试 5 次 | 抛出 RetryableError
```

第三行说明参数真的生效了——原本死写的 3 次，现在按 5 次跑。

注意这里的因果：**之所以需要三层，是因为参数在"函数出现之前"就要给出。** 顺序是死的：

```text
@retry(max_attempts=5)    参数在前，函数在后
@retry                    函数直接来
```

括号里的参数必须在看到函数之前就算出来，所以必须先返回一个"等着收函数"的东西——那就是 `decorator`。

**这个类比在哪里失效**：常说工厂像"定制壳：先说要求再拿壳"。但真正的定制流水线上，师傅可以先拿壳再改；这里不行，**顺序反了就是语法错误**。

### 4.5 v4：一个函数同时支持两种写法

现在手上是两个函数：`retry`（收函数）和 `retry_factory`（收参数）。用户想写 `@retry` 也想写 `@retry(max_attempts=5)`，不能让他们记两个名字。

做法：**给 `fn` 一个默认值 `None`，用"它是不是 None"来判断当前处在哪条路上。**

下面是**骨架**，`...` 表示"这里省略了内容"，**不是 Python 语法，照抄会 `SyntaxError`**。能直接跑的完整版在 §4.6：

```python
def retry(fn=None, *, max_attempts=3, sleep=time.sleep, ...):
    def decorator(func):
        ...                      # 真正的包装逻辑
        return wrapper

    if fn is None:               # 函数还没来 → 说明写的是 @retry(...)
        return decorator
    return decorator(fn)         # 函数已经来了 → 说明写的是 @retry
```

`None` 在这里叫**哨兵值**：一个约定俗成的"这里没东西"的标记。

两条分支对应两种写法：

| 你写的                      | Python 实际调用             | `fn` 是什么 | 走哪条分支 | 返回什么                         |
| ------------------------ | ----------------------- | -------- | ----- | ---------------------------- |
| `@retry`                 | `retry(fetch)`          | 函数对象     | 第二条   | `decorator(fetch)` = wrapper |
| `@retry()`               | `retry()`               | `None`   | 第一条   | `decorator`，随后被调用            |
| `@retry(max_attempts=5)` | `retry(max_attempts=5)` | `None`   | 第一条   | `decorator`，随后被调用            |

**为什么不会误判**：被装饰的东西永远是可调用对象，`fn` 不可能真的是 `None`。所以"`fn is None`"和"函数还没来"是精确对应的。

这个技巧有个名字叫 "conditional decorator"（条件装饰器）。它不是标准库里的什么功能，就是 `if` 加默认参数。

### 4.6 正式版 `retry` 逐行（`decorators.py` 第 27–65 行）

下面这段是 `w02/decorators.py` 的原文，**逐字复制**，不是重打的：

```python
def retry(
    fn: Callable[..., T] | None = None,
    *,
    max_attempts: int = 3,
    base_delay: float = 0.5,
    max_delay: float = 8.0,
    jitter: float = 0.5,
    sleep: Callable[[float], None] = time.sleep,
    on_retry: Callable[[int, LLMError, float], None] | None = None,
):
    """把 `retry_call` 包成装饰器，两种写法都支持。

        @retry                          # 用法一：一个括号都不写
        def f() -> str: ...

        @retry(max_attempts=5)          # 用法二：先配参数，再贴函数
        def g() -> str: ...

    参数含义与 `w02.errors.retry_call` 完全一致，这里只是原样往下传。
    """

    def decorator(func: Callable[..., T]) -> Callable[..., T]:
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> T:
            return retry_call(
                lambda: func(*args, **kwargs),
                max_attempts=max_attempts,
                base_delay=base_delay,
                max_delay=max_delay,
                jitter=jitter,
                sleep=sleep,
                on_retry=on_retry,
            )

        return wrapper

    if fn is None:          # @retry(...) 形式：函数还没来，先把 decorator 交出去
        return decorator
    return decorator(fn)    # @retry 形式：函数已经到了，直接包
```

它依赖的模块级东西（第 12–24 行）：

```python
from __future__ import annotations

import functools
import logging
import time
from collections.abc import Callable
from typing import Any, TypeVar

from w02.errors import LLMError, retry_call

T = TypeVar("T")

logger = logging.getLogger(__name__)
```

逐块说明：

| 位置        | 代码                                    | 作用                  | 细节                                               |
| --------- | ------------------------------------- | ------------------- | ------------------------------------------------ |
| 第 2 行     | `fn: Callable[..., T] \| None = None` | 明确 `fn` 可以被省略       | `...` 是"参数任意"的写法，`T` 是返回类型                       |
| 第 3 行     | `*`                                   | 它后面的参数**只能按关键字传**   | 防住 `retry(fetch, 5)` 这种位置传参，逼你写 `max_attempts=5` |
| 第 30–35 行 | 六个参数                                  | 与 `retry_call` 一一对应 | 本函数不解释它们的含义，只负责往下传                               |
| 第 48 行    | `def decorator(func)`                 | 内层工厂                | 注意参数名叫 `func`，和外层 `fn` 是两个不同的东西                  |
| 第 49 行    | `@functools.wraps(func)`              | 修元信息                | §4.3                                             |
| 第 50 行    | `def wrapper(*args, **kwargs)`        | 将来真正被调的函数           | §1.3                                             |
| 第 51–59 行 | `retry_call(lambda: func(...), ...)`  | 把调用裹成无参 lambda      | 这就是 v1 里那个别扭的 lambda，**从 20 个调用点收进了这 1 处**       |
| 第 61 行    | `return wrapper`                      | 交出新函数               | —                                                |
| 第 63–65 行 | `if fn is None: ...`                  | 双形态分叉               | §4.5                                             |

**关于类型注解的诚实说明**：`retry` 没有写返回值注解。完整写法需要 `ParamSpec` 加 `@overload`（两个重载：收函数返回函数、收参数返回装饰器），否则类型检查器无法表达"返回类型取决于你传了什么"。本节故意省掉，是为了不让注解盖过装饰器本身。运行行为完全不受影响，只是 IDE 的类型提示会退化成 `Any`。

| 参数                                    | 含义               | 本节哪里用到                           |

### 4.7 正式版 `timed` 逐行（第 68–97 行）

第二个装饰器解决"计时"这件事。它是**和 `retry` 完全独立的另一个例子**，用来证明装饰器这个模式不是只能做重试。

```python
def timed(
    fn: Callable[..., T] | None = None,
    *,
    timer: Callable[[], float] = time.perf_counter,
    sink: Callable[[str, float], None] | None = None,
):
    """记录函数耗时，成功和失败都记。

    `timer` 和 `sink` 都是可注入的：测试里换掉它们，就能在不真等的前提下
    断言「耗时被记录了几次、每次多少」。
    """

    def decorator(func: Callable[..., T]) -> Callable[..., T]:
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> T:
            started = timer()
            try:
                return func(*args, **kwargs)
            finally:
                elapsed = timer() - started
                if sink is not None:
                    sink(func.__name__, elapsed)
                else:
                    logger.info("%s 耗时 %.3fs", func.__name__, elapsed)

        return wrapper

    if fn is None:
        return decorator
    return decorator(fn)
```


两个设计点值得单独说。

**① `finally` 而不是写在 `return` 后面**

```python
            started = timer()
            try:
                return func(*args, **kwargs)
            finally:
                elapsed = timer() - started
```

如果写成下面这样（**错误写法，摆出来做对比**，语法没错，但计时会漏掉失败的调用）：

```python
            started = timer()
            result = func(*args, **kwargs)     # 这行抛异常，下面全部不执行
            elapsed = timer() - started
            return result
```

一旦 `func` 抛异常，计时就被跳过了——而**恰恰是失败的调用最需要知道耗时**（"这个请求是立刻 401 了，还是卡了 30 秒才超时"）。

`finally` 保证无论正常返回还是抛异常，计时都会执行。实测验证（`test_timed_异常时也记录`）：

```text
记录到 [('boom', 0.5)]      # 函数抛了 ValueError，耗时照样被记下
```

**② `timer` 和 `sink` 都是参数**

`timer` 默认 `time.perf_counter`（单调递增的高精度计时器，不受系统改时间影响），`sink` 默认 `None` 表示走 `logger.info`。

把它们做成参数，测试才能在不真等 0.5 秒的前提下验证"记了几次、每次多少"：

```python
    ticks = iter([0.0, 0.5])
    records: list[tuple[str, float]] = []

    @timed(timer=lambda: next(ticks), sink=lambda name, s: records.append((name, s)))
    def boom() -> None:
        raise ValueError("故意失败")
```

`ticks` 是一个迭代器：第一次调 `timer()` 拿到 `0.0`，第二次拿到 `0.5`，于是算出的耗时**必然**是 `0.5`。这就是 02 里 `sleep` 注入的同一个技巧——**凡是不确定的、慢的、有副作用的外部依赖，都做成参数**。

`logger.info(...)` 用的是模块级 `logger`（第 24 行 `logging.getLogger(__name__)`），`__name__` 在这里是 `w02.decorators`。**05 节讲怎么配置它**——现在它默认不会显示任何东西（根 logger 默认级别是 `WARNING`，`INFO` 被过滤掉了），这不影响测试。

### 4.8 叠加顺序：谁在外层，谁看到总耗时

两个装饰器叠在一起时，**下面的先装、上面的后装**（下面这段是形状示意，`f` 的函数体用 `...` 省略）：

```python
@timed          # 后装 → 在外层
@retry          # 先装 → 在内层
def f(): ...
```

等价于 `f = timed(retry(f))`。调用 `f()` 时，先进 `timed` 的 wrapper，再进 `retry` 的 wrapper，再进原函数。

顺序一换，计时结果完全不同。实测两个场景：

| 场景 | 写法                      | 记录条数    | 每条是什么        |
| -- | ----------------------- | ------- | ------------ |
| A  | `@timed` 在外，`@retry` 在内 | **1 条** | 包含 3 次尝试的总时间 |
| B  | `@retry` 在外，`@timed` 在内 | **3 条** | 每次尝试各自的耗时    |

A 的代码（`_demo()` 第 157–166 行）：

```python
    @timed(sink=make_sink(bucket_a))
    @retry(sleep=lambda seconds: time.sleep(0.02))
    def task_a() -> str:
```

实测输出：

```text
      A. @timed 在外层 → 记 1 条，包含全部重试
          [('task_a', 0.041)]
```

B 的代码（第 172–181 行）：

```python
    @retry(sleep=lambda seconds: time.sleep(0.02))
    @timed(sink=make_sink(bucket_b))
    def task_b() -> str:
```

实测输出：

```text
      B. @retry 在外层 → 记 3 条，各是单次尝试
          [('task_b', 0.0), ('task_b', 0.0), ('task_b', 0.0)]
```

**为什么 B 全是 `0.0`**：那两次 `sleep(0.02)` 发生在 `retry` 这一层，而 `timed` 在它**里面**，只包住了函数本身。函数本身没耗时，所以每次记到 `0.0`。这正好反过来印证了 A 的 `0.041` 里包含了等待时间。

怎么选：

| 你想知道                | 该把谁放外层      |
| ------------------- | ----------- |
| 这个函数端到端一共花了多久（含重试）  | `@timed` 在外 |
| 每次尝试分别多慢（判断是不是越来越慢） | `@timed` 在内 |

**同类相叠的坑**：`@timed` 叠 `@timed` 会记两条，`@retry` 叠 `@retry` 会变成 3×3=9 次尝试。装饰器不会帮你检查重复。

**这个类比在哪里失效**：常说装饰器像"洋葱一层层剥"。但洋葱是往内剥，装饰器是**从外往内进入、从内往外返回**——`timed` 的 `finally` 是在内层全部走完之后才执行的。所以用"进出两道门"来想更准确。

```python
"""W2-03 · 装饰器：把重试、计时从业务函数里搬出去。

一句话：装饰器 = 接收函数、返回新函数的函数；`@` 只是语法糖。

为什么需要这一层：
  1. `retry_call(fn)` 要求调用点现场造 lambda，20 个调用点就有 20 个 lambda；
  2. 重试 / 计时 / 打日志属于「横切关注点」，写进业务函数会把主逻辑淹掉；
  3. 包一层 wrapper 会丢掉 __name__ / __doc__ / 签名，必须用 functools.wraps 补回来。

运行演示：..\\.venv\\Scripts\\python.exe -m w02.decorators
"""
from __future__ import annotations

import functools
import logging
import time
from collections.abc import Callable
from typing import Any, TypeVar

from w02.errors import LLMError, retry_call

T = TypeVar("T")

logger = logging.getLogger(__name__)


def retry(
    fn: Callable[..., T] | None = None,
    *,
    max_attempts: int = 3,
    base_delay: float = 0.5,
    max_delay: float = 8.0,
    jitter: float = 0.5,
    sleep: Callable[[float], None] = time.sleep,
    on_retry: Callable[[int, LLMError, float], None] | None = None,
):
    """把 `retry_call` 包成装饰器，两种写法都支持。

        @retry                          # 用法一：一个括号都不写
        def f() -> str: ...

        @retry(max_attempts=5)          # 用法二：先配参数，再贴函数
        def g() -> str: ...

    参数含义与 `w02.errors.retry_call` 完全一致，这里只是原样往下传。
    """

    def decorator(func: Callable[..., T]) -> Callable[..., T]:
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> T:
            return retry_call(
                lambda: func(*args, **kwargs),
                max_attempts=max_attempts,
                base_delay=base_delay,
                max_delay=max_delay,
                jitter=jitter,
                sleep=sleep,
                on_retry=on_retry,
            )

        return wrapper

    if fn is None:          # @retry(...) 形式：函数还没来，先把 decorator 交出去
        return decorator
    return decorator(fn)    # @retry 形式：函数已经到了，直接包


def timed(
    fn: Callable[..., T] | None = None,
    *,
    timer: Callable[[], float] = time.perf_counter,
    sink: Callable[[str, float], None] | None = None,
):
    """记录函数耗时，成功和失败都记。

    `timer` 和 `sink` 都是可注入的：测试里换掉它们，就能在不真等的前提下
    断言「耗时被记录了几次、每次多少」。
    """

    def decorator(func: Callable[..., T]) -> Callable[..., T]:
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> T:
            started = timer()
            try:
                return func(*args, **kwargs)
            finally:
                elapsed = timer() - started
                if sink is not None:
                    sink(func.__name__, elapsed)
                else:
                    logger.info("%s 耗时 %.3fs", func.__name__, elapsed)

        return wrapper

    if fn is None:
        return decorator
    return decorator(fn)


def _demo() -> None:
    def fake_sleep(seconds: float) -> None:
        print(f"      …… 实际会睡 {seconds:.2f}s（演示里不睡）")

    print("① @retry 不带任何参数")
    calls: list[str] = []

    @retry(sleep=fake_sleep)
    def fetch(text: str) -> str:
        calls.append(text)
        if len(calls) < 3:
            raise TimeoutError("mock timeout")
        return f"摘要：{text}"

    print("      返回:", fetch("原文"))
    print("      调用次数:", len(calls))
    print("      __name__:", fetch.__name__)

    print()
    print("② @retry(max_attempts=5)：次数可配")
    attempts: list[int] = []

    @retry(max_attempts=5, sleep=lambda seconds: None)
    def always_timeout() -> None:
        attempts.append(1)
        raise TimeoutError("mock timeout")

    try:
        always_timeout()
    except LLMError as exc:
        print(f"      共尝试 {len(attempts)} 次后放弃，抛出 {type(exc).__name__}")

    print()
    print("③ @timed：记录单次耗时")
    records: list[tuple[str, float]] = []
    ticks = iter([0.0, 0.25])

    @timed(timer=lambda: next(ticks), sink=lambda name, s: records.append((name, s)))
    def write_doc() -> str:
        return "ok"

    write_doc()
    print(f"      记录到 {records}")

    print()
    print("④ 叠加顺序：谁在外层，谁看到的是总耗时")

    def make_sink(bucket: list[tuple[str, float]]) -> Callable[[str, float], None]:
        def sink(name: str, elapsed: float) -> None:
            bucket.append((name, round(elapsed, 3)))

        return sink

    print("      A. @timed 在外层 → 记 1 条，包含全部重试")
    bucket_a: list[tuple[str, float]] = []
    state_a = {"calls": 0}

    @timed(sink=make_sink(bucket_a))
    @retry(sleep=lambda seconds: time.sleep(0.02))
    def task_a() -> str:
        state_a["calls"] += 1
        if state_a["calls"] < 3:
            raise TimeoutError("mock timeout")
        return "ok"

    task_a()
    print("         ", bucket_a)

    print("      B. @retry 在外层 → 记 3 条，各是单次尝试")
    bucket_b: list[tuple[str, float]] = []
    state_b = {"calls": 0}

    @retry(sleep=lambda seconds: time.sleep(0.02))
    @timed(sink=make_sink(bucket_b))
    def task_b() -> str:
        state_b["calls"] += 1
        if state_b["calls"] < 3:
            raise TimeoutError("mock timeout")
        return "ok"

    task_b()
    print("         ", bucket_b)


if __name__ == "__main__":
    _demo()
```

```python
import openai

        status, request=httpx.Request("POST", "https://api.example.com")

    import functools

    def without_wraps(func):
        def wrapper(*args, **kwargs):
            return func(*args, **kwargs)
```

## 6. 收口

### 6.1 速查卡：什么时候该写装饰器

| 你的处境                              | 该不该用装饰器                    |
| --------------------------------- | -------------------------- |
| 逻辑只在一个函数里出现一次                     | **不用**，直接写函数体里             |
| 同一段"前后动作"要在 3 个以上函数里重复            | **用**，横切关注点                |
| 需要在函数调用**前后**插入行为（计时、日志、鉴权、缓存、重试） | **用**                      |
| 想改变函数的返回值类型或参数个数                  | **不用**，那不是装饰器该干的           |
| 只是为了少写两行 `retry_call(...)`        | 看情况，1 处不值得，5 处以上就值得        |
| 需要给装饰器本身配置参数                      | **用工厂形态**（`fn=None` 或两层函数） |

四句话记住：

1. **装饰器 = 收函数、返函数的函数**，`@` 只是 `f = deco(f)` 的语法糖。
2. **必须加 `@functools.wraps(func)`**，否则 `__name__`/`__doc__`/签名全丢，pytest 会因为看不到 fixture 参数而报"缺参数"。
3. **要传参数就套两层**，用 `fn=None` 让一个函数同时支持 `@retry` 和 `@retry(...)`。
4. **叠加时下面的先装**，写在上面的在外层，看到的是总耗时。
