# 模型切换：从"写死一个模型"到"界面上换一个"

这份文档回答四个问题：

1. 为什么不能把模型名写死在代码里；
2. 换模型时除了改名字，还必须改什么（只改名字会踩一个必踩的坑）；
3. 界面上那 123 个选项是怎么来的，为什么是 123 个而不是 184 个；
4. 想加一个新模型 / 换一个服务商，具体动哪里。

---

## 1. 它解决什么

改造前，模型只由 `.env` 里的 `LLMKIT_MODEL` 决定，改一次要重启服务。
现在界面上有一个下拉框，选了就对之后的**提问、生成画像、自检**全部生效，
不改配置文件、不重启，刷新页面还记着上次选的。

这不是"多个下拉框看着专业"，它有一个具体用途：
**同一份资料、同一个问题，用不同模型问一遍，直接对比答案差异**。
判断"某个模型是不是更适合我的资料"，只能这么看，读评测文章没用——
评测文章用的是别人的资料。

## 2. 数据怎么流过去

```
界面 <select id="model">
   │  选择存 localStorage，发请求时带 model 字段
   ▼
POST /api/ask            {"question": ..., "model": "qwen3.8-max"}
POST /api/docs/{id}/profile?model=...
POST /api/docs/{id}/selfcheck?model=...
   │
   ▼
Studio.settings_for(model)     ← 复制一份配置，只改 model
   │                           （密钥、地址、超时原样带过去）
   ▼
answer_question(..., settings=cfg, max_tokens=catalog.max_tokens_for(model))
   │
   ▼
llmkit.client.ask()  →  openai SDK  →  上游
```

`settings_for` 是**复制**而不是改动 `self.settings`，原因写在 `studio/service.py` 里：
`Settings` 是 frozen 的，而且一个常驻服务随时可能被两个请求同时问到不同模型——
把"当前模型"存成实例状态，第二个请求就会悄悄用上第一个选的那个。
（这个 bug 不会报错，只会让答案莫名其妙地来自另一个模型，极难查。）

没指定 `model`、或传了空串，一律回落到 `.env` 的 `LLMKIT_MODEL`。
空串要当成"没选"处理：前端下拉框没选中时很容易发出 `model=""`，
按"模型名不存在"报错就太不讲理了。

## 3. 只改名字会踩的坑：输出预算

这是这次改造里唯一一个**必须一起改**的东西，实测出来的。

推理型模型（先想后答）把"思考的 token"和"回答的 token"算进**同一个**
`max_tokens` 池子。改造前 `qa/answer.py` 写死 `max_tokens=800`，
于是选了这类模型之后：思考吃光 800，正文为空串，`llmkit/client.py` 判为空正文
→ 重试三次 → 报错"模型返回空正文"。

用户看到的是一句"模型坏了"，而真正的原因只是"这个模型需要更多预算"。

### 单次裸调用实测（2026-11-18，同一句话，同一把密钥）

提问：`一句话说明什么是信息熵`

| 模型 | max_tokens | 耗时 | 正文 token | reasoning | 结果 |
|---|---|---|---|---|---|
| qwen-max | 200 | 1.1 s | 22 | 0 | 正常 |
| deepseek-v4.1-flash | 200 | 1.1 s | 70 | 0 | 正常 |
| qwen3.8-flash | 200 | 1.5 s | 79 | 0 | 正常 |
| qwen-plus | 200 | 2.0 s | 34 | 0 | 正常 |
| qwen3.8-max | 200 | 4.1 s | 72 | 0 | 正常 |
| glm-5.3 | 200 | 4.3 s | — | — | **截断成"信息"** |
| kimi-k3.1-pro | 200 | 7.2 s | **0** | — | **空正文** |
| deepseek-v4-pro | 200 | 8.5 s | **0** | — | **空正文** |
| qwen3.7-plus | 200 | 19.5 s | 506 | — | 正常但很慢 |
| qwen3.5-flash | 200 | 30.6 s | 2582 | — | 极慢，不进推荐表 |

同一批模型、把预算放开之后：

| 模型 | max_tokens | 耗时 | 正文 | reasoning | finish_reason |
|---|---|---|---|---|---|
| deepseek-v4-pro | 4000 | 16.9 s | 668 | 621 | stop |
| kimi-k3.1-pro | 4000 | 31.3 s | 862 | 772 | stop |
| qwen3.7-plus | 4000 | 10.3 s | 484 | 439 | stop |
| glm-5.3 | 1000 | 9.4 s | 805 | 727 | stop |

所以规则是：

- **非推理型**：`max_tokens=1600`。上限不影响速度（模型自己 `stop` 就停），
  但给到 800 会让"其实需要想一想"的模型直接吐空。宽一点没有代价。
- **推理型**：`max_tokens=4000`。问答 prompt 塞了 6000 字符上下文，思考只会比裸调用更长。

`reasoning=True` 是**实测标注**，不是按名字猜：
`qwen3.7-plus` 名字看不出会思考，实测 reasoning=439；
`qwen3.8-max` 名字看着很重，实测 reasoning=0。
猜错的代价是真金白银和几十秒延迟，所以没测过的模型一律按非推理型处理
（1600），不替它做决定。

### 端到端实测（30 页中文资料，top_k=5，问"因子得分是怎么算出来的？"）

| 模型 | 耗时 | 引用 | 越界 | 结论 |
|---|---|---|---|---|
| qwen3.8-flash | 13.9 s | p21-22、p22 | 0 | 加了"结论 / 依据"结构 |
| qwen3.8-max | 24.4 s | p20、p22、p21 | 0 | 三个出处，更全 |
| deepseek-v4-pro | 11.5 s | p20、p22 | 0 | 推理型，最简洁 |

三个模型的引用都对得上页，说明换模型没有破坏"引用可核验"这条底线。

## 4. 那 123 个选项是怎么来的

```
GET /api/models                    （服务端缓存 10 分钟）
   │
   ├─ 上游 GET {base_url}/models  →  184 个模型
   │      │
   │      ├─ 滤掉非聊天模型（image / tts / asr / ocr / embedding /
   │      │   rerank / realtime / livetranslate / omni / mt- …）→ 剩 61 个被去掉
   │      │
   │      └─ 9 个进"推荐"组（按 catalog.RECOMMENDED 的顺序 + 实测备注）
   │         114 个进"全部聊天模型"组（字母序）
   │
   └─ 上游问不到  →  只剩推荐表，下拉框变黄，鼠标悬停显示原因
```

为什么过滤而不是全列：选中 `qwen-image-3.0` 去问"什么是方差"，上游回一句
参数错误——这不是用户该遇到的。黑名单只挡明确不能聊的（画图、语音、向量），
新出的聊天模型不会被误挡（白名单才会误挡）。

为什么推荐表要写死：**接口只能告诉你"存在"，告诉不了你"多快、要不要更多预算"**。
那部分只能实测。所以清单分两半——存在的部分问上游，好坏的部分靠实测。

三种 `source`，前端要能区分：

| source | 含义 | 界面表现 |
|---|---|---|
| `upstream` | 上游真实清单 | 正常 |
| `fallback` | 上游问不到（超时/网络/端点不支持） | 下拉框变黄，悬停显示原因 |
| `unconfigured` | 连密钥都没有 | 下拉框变黄，只剩推荐表 |

`fallback` 不抛异常是刻意的：模型清单拉不到时整页白屏，用户连"上传资料"都做不了。
降级不丢人，静默降级才丢人——所以 `note` 字段一定写清原因，界面上一定看得见。

还有一个细节：如果 `.env` 里的默认模型不在上游清单里（换了服务商、留着旧名字），
`note` 会直接说"当前模型 X 不在上游清单里"。不提示的话，用户只会看到"提问失败"。

## 5. 想加一个模型 / 换一家服务商

### 加一个模型（同一个服务商）

改 `.env` 就行，界面上下拉框立刻能看到——只要它在 `GET /models` 里。
不在推荐组的会出现在"全部聊天模型"里，按默认 1600 预算跑。

如果它其实是推理型，会吐空正文，那就再做一个动作：
在 `llmkit/catalog.py` 的 `RECOMMENDED` 里加一行，带上实测的耗时和 `reasoning=True`：

```python
ModelEntry(
    id="你的模型名",
    note="推理型，先想后答（实测 12.3 s）",
    reasoning=True,
    max_tokens=REASONING_MAX_TOKENS,
),
```

`note` 里必须写实测耗时——写"强大""高效"这种词等于没写，用户没法据此选。

### 换一家服务商

改 `.env` 三行：

```bash
LLMKIT_API_KEY=...
LLMKIT_BASE_URL=https://服务商的/v1
LLMKIT_MODEL=默认模型名
```

只要对方兼容 OpenAI 协议（`/chat/completions` + `/models`），代码一行不用动。
不兼容的话（没有 `/models`）也能用：`source` 会是 `fallback`，
下拉框只剩内置推荐表——里面全是百炼的模型名，对方没有就会调用失败。
这种情况把 `RECOMMENDED` 换成对方的模型即可。

## 6. 已知限制

- **成本显示会是 0。** 百炼的单价随模型、上下文长度、缓存命中而变，
  官方定价页是按模型分页列的，没有一处能一次读全。没实测到准确数字就不编，
  所以 `.env` 里 `LLMKIT_PRICE_IN/OUT` 是 0，界面上的「¥」那一栏不显示。
  想让成本显示出来，就自己填单价——但注意**它是跟着模型变的**，换模型后这个单价就不准了。
- **不支持流式。** 界面是"等一整段答案"，所以 24 秒的 qwen3.8-max 会让人干等。
  要做流式得改 `/api/ask` 为 SSE，前端也要改成逐段追加，属于另一件事。
- **清单缓存 10 分钟。** 刚上架的模型最多等 10 分钟，或访问 `/api/models?refresh=1`。
- **没有"记住每次用了哪个模型"。** 答案卡片会显示本次用的模型，但历史不落盘。

## 7. 验收标准

| # | 要求 | 判据 | 实测 |
|---|---|---|---|
| M1 | 界面上能换模型 | 提问卡头部有下拉框，分组为「推荐」+「全部聊天模型」 | 123 个选项：9 推荐 + 114 其余 |
| M2 | 换了真的换 | 请求体内 `model` 真的到了上游，答案卡片显示本次模型 | `_last_call(s)["model"]` 断言 + 三个模型端到端跑通 |
| M3 | 推理型不会吐空 | 选 `deepseek-v4-pro` 能正常答 | `max_tokens=4000`，实测正文 668 token，引用越界 0 |
| M4 | 上游挂了界面能开 | `/api/models` 失败时降级为推荐表 | 单测覆盖：假客户端无 `models` 接口 → `source=fallback` |
| M5 | 不弄坏原有能力 | 全量测试全绿 | **423 passed / 12 skipped**（新增 catalog 12 条、service 7 条、api 4 条；顺手删掉两组重复定义的测试，它们原来被后一份覆盖，等于没跑） |
| M6 | 选择能记住 | 刷新页面还是上次选的；选过的模型已失效时自动回落 | `localStorage` + 清单校验（代码审查，无 headless 测试） |

## 8. 改动的文件

| 文件 | 改了什么 |
|---|---|
| `llmkit/catalog.py` | **新增**。推荐表（含实测耗时与预算）、非聊天模型黑名单、上游清单拉取与 10 分钟缓存、三种 source 的降级 |
| `llmkit/tests/test_catalog.py` | **新增** 12 条。过滤、预算、缓存过期、过期时钟、上游失败、默认模型不在清单 |
| `qa/answer.py` | `answer_question(..., max_tokens=)`；`Answer.model` 记录实际模型 |
| `studio/service.py` | `settings_for()` / `models()`；`ask` / `profile` / `selfcheck` 接受 `model`；输出预算按模型查 |
| `studio/selfcheck.py` | `run_selfcheck(..., model=)`；报告里记录本次用的模型 |
| `studio/api.py` | `GET /api/models`；`/api/ask` 读 `model`；画像与自检的 `model` 查询参数；`health` 加 `has_key` |
| `studio/static/index.html` | 提问卡头部的模型下拉（分组、悬停备注、降级变黄）、`localStorage` 记忆、答案与自检结果显示本次模型、390px 下整行独占 |
| `.env` | 密钥与地址换成阿里云百炼；默认模型 `deepseek-v4.1-flash`；单价置 0（原因见 §6） |
