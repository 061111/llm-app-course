# 上传服务与中文资料理解（M5）

> 一句话：在原有四层之上加了一层 `studio`，让用户**上传自己的资料**（中文也可以），
> 系统从中抽出术语与领域措辞，把这些词注入问答，并且**每一个结论都能翻回原文**。

---

## 0. 结论先说：能不能做

能做，而且已经做完了。下面是每条要求的完成情况与证据，证据都可以复现（命令见 §2）。

| 要求 | 结论 | 实测证据 | 边界 |
|---|---|---|---|
| 支持用户上传资料 | 能 | PDF / TXT / MD，30 页中文 PDF 解析 8 秒内完成，59 块 | 扫描件需 OCR，本服务不含 |
| 中文文档理解 | 能 | 10 道中文题 hit@1 **10/10**、MRR **1.000** | 开卷成绩：题是照着原文写的 |
| 提取关键术语 | 能 | 30 页资料抽出 443 个候选，Top 40 中 37 个是领域术语 | 小样本（<2000 汉字）质量下降 |
| 提取专业表达 / 领域措辞 | 能 | 模型生成 5~6 条"可能怎么问"，全部绑定已校验术语 | 依赖模型可用，不可用则降级为空 |
| 据此补充项目内容 | 能 | 术语进 prompt（强制用词一致）+ 措辞进检索扩展 | 扩展只在首轮零命中时触发 |
| 不编造 | 能，且有计数 | 真实调用：16 个术语 **0 个被拒**（都被原文验证）；注入实验：1 个假术语 **100% 被拒** | 领域名与一句话概括无法机械校验，只限长、标来源 |
| 结果展示 | 能 | 单页界面：资料卡片 / 术语表（含页码）/ 画像 / 问答（含依据） | 本地单机，无鉴权 |
| 异常处理 | 能 | 12 类错误码，全部带"用户下一步该做什么" | — |

**"是否可实现"的诚实回答**：能做，但必须接受三个前提。

1. **中文检索不能靠"效果好一点"，得换分词方式。** 原来的分词器把一整句中文当成一个词，中文资料命中率是 **0**，不是"差"。这一步是修 bug，不是优化。
2. **术语表不能直接问模型"有哪些术语"。** 那样得到的词表里必然混进不在原文里的词，而且人眼查不出来。必须先统计、再让模型从候选里挑，最后逐字回原文验证。
3. **"不编造"只能靠机械校验，不能靠提示词。** 提示词写得再严，也没有一行代码能证明模型守规矩；而"这个词在不在原文里""这个页码存不存在"是可以一行代码判定的。

## 1. 功能范围

### 做什么

| 功能 | 说明 | 入口 |
|---|---|---|
| 上传 | PDF / TXT / MD，单文件 ≤ 50 MB，最多 200 份 | `POST /api/docs` |
| 解析 | 复用 `corpus/parser.py`：按 bbox 删页码、私有区符号映射、书签取标题；TXT/MD 用虚拟分页 | 上传时自动 |
| 切块 | 复用 `corpus/chunker.py`，`page` 模式 + 1200 字上限（与课程语料同一套参数） | 上传时自动 |
| 中文检索 | 汉字切二元组，与英文分词共存；英文资料仍走"中文问题→英文关键词" | 提问时自动 |
| 术语抽取 | PMI 凝固度 + 左右邻字熵，每个术语带页码与原文片段 | `GET /api/docs/{id}/terms` |
| 领域画像 | 模型从候选里挑术语、写说明、生成"可能怎么问"；全部机械校验后落盘 | `POST /api/docs/{id}/profile` |
| 问答 | 术语注入 prompt、引用格式强制、越界检测、拒答识别 | `POST /api/ask` |
| 展示 | 单页界面：上传、文档卡片、术语表、画像、问答与依据 | `GET /` |

### 不做什么（以及为什么）

| 不做 | 理由 |
|---|---|
| OCR | 需要额外模型与依赖；当前用"平均每页 <20 字符"识别扫描件并明确拒绝，比偷偷返回空答案好 |
| 用户体系 / 鉴权 | 本机单用户工具。**没有鉴权就绝不绑 0.0.0.0** —— 见 `studio/__main__.py` 的注释 |
| 多租户索引隔离 | 所有资料共用一个 BM25 池。资料多于几十份时 IDF 会互相稀释，需要按文档集建独立索引（见 §7） |
| 增量索引 | 每次提问时按需解析并缓存在内存；没有倒排索引、没有持久化索引文件 |
| 试卷/表格结构还原 | 沿用 M2 的已知限制：表格抽出来是竖排，列关系丢失 |
| 自动重建旧画像 | 上传新文档**不会**让旧文档的画像失效。术语统计是全库的，重建是用户的显式动作 |

## 2. 验收标准

每条都是**可机械判定**的，不是"看起来不错"。最后一列是可复现的命令。

| 编号 | 验收项 | 判定方式 | 实测 | 复现 |
|---|---|---|---|---|
| A1 | 合法文件能解析成块 | 上传后 `pages>0`、`chunks>0`、`lang∈{zh,en,mixed}` | 30 页 / 59 块 / zh | `pytest studio/tests/test_ingest.py` |
| A2 | 中文问题能命中中文正文 | 10 道题，答案页出现在 top-k | hit@1 **10/10**、hit@3 **10/10**、MRR **1.000** | `LLMKIT_CN_SAMPLE=... pytest studio/tests/test_acceptance_cn.py -s` |
| A3 | 术语出处可回查 | 用 `(page,start,end)` 切原文，必须等于术语本身 | 20/20 全部相等 | `pytest studio/tests/test_glossary.py` |
| A4 | 模型不能发明术语 | 输出里每个术语逐字在原文查找，找不到即 `rejected` | 真实调用 16/16 通过、rejected **0**；注入实验 1/1 被拒 | `pytest studio/tests/test_profile.py` |
| A5 | 说明里的数字必须有据 | 说明中的每个数字须在该术语所在页出现 | 注入"共同度一般大于 0.7"→ 说明被丢弃、术语保留 | 同上 |
| A6 | 引用不能越界 | 引用页必须被本次检索到的块覆盖 | 真实问答 5/5 题 `unsupported=()` | `pytest studio/tests/test_service.py` |
| A7 | 资料外问题要拒答 | 回答"资料未覆盖"且无引用 | 真实模型：量子纠缠 / 法国大革命 **2/2 拒答** | 手工（需密钥），见 §6 |
| A8 | 异常要说得出口 | 每个错误有 `code` + `hint`，HTTP 码正确 | 12 类逐个断言 | `pytest studio/tests/test_api.py` |
| A9 | 不能弄坏原有能力 | 原有 283 条测试全绿 | **393 passed**（283 + 110 新增）；缺中文样本时 381 passed + 12 skipped | `pytest` |
| A10 | 成本与延迟可接受 | 单次画像 / 单次问答的成本与耗时 | 画像 ¥0.032 / 19.5 s；问答 ¥0.010 / 2.8 s | 见 §6 |

> A2 的 10/10 是**开卷成绩**：题目是我对着原文写的，答案就在这 30 页里。
> 它证明链路通、切片准、术语对得上，**不证明泛化**。这一点和原项目对 18/18 的声明一致。

## 3. 架构：新增的第 5 层

```
                  ┌──────────────────────────────┐
   用户 ── HTTP ──▶│ studio/api.py  (FastAPI)     │
                  │   ├ service.py  编排 + 缓存   │
                  │   ├ library.py  上传登记表    │
                  │   ├ ingest.py   安检 + 解析   │
                  │   ├ glossary.py 术语抽取      │
                  │   └ profile.py  画像 + 校验   │
                  └───────┬──────────────┬───────┘
                          │              │
              ┌───────────▼───┐   ┌──────▼────────┐
              │ qa            │   │ retrieval     │
              │ prompt/answer │◀──│ bm25/search   │
              └───────┬───────┘   └──────┬────────┘
                      │                  │
                      ▼                  ▼
              ┌───────────────┐   ┌──────────────┐
              │ llmkit        │   │ corpus       │
              │ 唯一 import    │   │ parse/chunk  │
              │ openai 的地方  │   │ （不知道 Web）│
              └───────────────┘   └──────────────┘
```

依赖仍然是**单向**的：`studio → qa/retrieval → corpus`，`llmkit` 只被需要调模型的地方调用。
`corpus` 对 `llmkit` 依然零依赖，所以"上传一个 PDF 只看解析结果"不需要密钥。

**为什么单独一层，而不是塞进 corpus 或 qa？**

- 塞进 `corpus`：`corpus` 目前是"离线、纯函数、零网络"。上传要处理 HTTP 文件流、错误码、manifest 读写，混进去会毁掉它"断网也能跑"的性质。
- 塞进 `qa`：`qa` 只该知道"给定问题和片段怎么答"，不该知道文件从哪来。
- 单独一层还有一个好处：删掉 `studio/`，剩下四层和 283 条测试完全不受影响 —— 这是可以验证的（`rm -rf studio && pytest`）。

## 4. 七个关键决定

### 4.1 中文分词用字二元组，不引入 jieba

**问题**：`TOKEN_RE = [^\W\d_]+|\d+(\.\d+)?` 里 `\w` 含汉字，一整句中文变成一个词元。

实测（改造前）：

```
问题分词:    ['贝叶斯分类器的核心假设是什么']
正文分词:    ['朴素贝叶斯分类器假设各属性在给定类别下条件独立']
交集:        set()  → BM25 得分恒为 0
```

**选择**：按"连续汉字段 / 其他段"切开，汉字段切二元组（`朴素贝叶斯` → `朴素/素贝/贝叶/叶斯`），其他段走原规则。

**为什么不 jieba**：多一个 20 MB 词典依赖；而且检索不需要语言学正确，只需要"同一个词在文档和查询里被切成同一串符号"。代价是词表变大，由 IDF 自动压掉"的是/我们"这类高频二元组。

**英文零回归**：`test_英文分词与改造前逐词一致` 逐词断言，283 条原测试全绿。

### 4.2 两张登记表：评测语料 vs 上传语料

`corpus/docs.py` 的 `DOCS` 被黄金集锁死（`{g.doc_id} == set(DOCS)`、页数合计 199）。
用户上传的文档一旦塞进 `DOCS`，18 题评测立刻被污染，283 条测试里至少 2 条变红。

所以另起一张可写表：`artifacts/library.json`。两个关键差别：**可写**、**带 sha256**（重复上传要能识别，否则同一个文件在索引里出现两份，BM25 的 IDF 被稀释）。

**doc_id 的约束**：引用格式 `【doc_id:pN】` 的正则只接受 `[A-Za-z0-9_]+`，所以中文文件名不能直接当 doc_id。规则：取文件名里的 ASCII 字母做 slug，没有就退化成 `u001`。实测踩过一次坑：`（计算题 3-6章 ）` 洗出的 slug 是 `3_6`，合法但没有信息量、还容易被读成页码 —— 于是加了"必须含至少一个字母"。

### 4.3 术语：先统计候选，再让模型从候选里挑

直接问模型"列出这份资料的术语"，它会给出**看起来专业但不在原文里**的词。

所以分两步：

1. **统计层**（`glossary.py`）：从字面捞候选，每个候选带页码和上下文。候选来自原文，天生不可能编造。
   判据是两条经典的新词发现指标：
   - **凝固度**（PMI，取所有切分点里最松的一刀）：`P(距离矩阵) ≫ P(距离)·P(矩阵)` → 它是个整体；
   - **左右邻字熵**：一个词能出现在各种上下文里，左右相邻的字应该很杂。
2. **模型层**（`profile.py`）：只能从候选里选、只能逐字复制。

阈值是调出来的：`freq≥3 / PMI≥2.0 / 熵≥1.0`，在 30 页 / 23528 汉字上留 443 个候选，
Top 30 里 27 个是本领域术语（因子、载荷、公共因子、协差阵、方差贡献、主成分、判别函数、马氏距离…）。

**调参过程里的两次失败**（都写在代码注释里）：

| 版本 | 现象 | 修正 |
|---|---|---|
| 熵把行首边界当邻字 | PPT/笔记里术语常在行首，左边全是 `^` → 熵 = 0 → "距离矩阵"被误杀 | 边界标记不参与熵计算；一侧样本 <2 时用另一侧 |
| 去重规则"短词频次 < 2×长词频就丢" | "氏距离"(27) vs "马氏距离"(11)：27 ≥ 22 → 碎片被留下 | 改成"被更长词吃掉的次数 ≥ 0.8×自身频次"才丢 |

### 4.4 三道机械校验：这是"不编造"的全部实现

| 模型能做什么 | 校验方式 | 不合格怎么办 |
|---|---|---|
| 从候选里挑术语 | 逐字在原文里查找 | 丢进 `rejected`，计入编造数 |
| 给术语写一句说明 | 说明里的每个数字必须在该术语所在页出现 | 丢弃说明，保留术语（`notes_dropped`） |
| 写"用户可能怎么问" | 问题引用的术语必须已通过校验 | 丢弃这条问题 |
| 写领域名 / 一句话概括 | 无法机械校验（这是概括，不是事实） | 限长 16/60 字 + 标 `source` 字段 |

**页码一律由系统重算**：prompt 里没有让模型输出页码，输出结构里也没有这个字段。
模型没有任何机会编一个页码。

代价是模型只能"选"不能"造"。换来的是可以量化的指标：**编造术语数**，验收要求为 0。

### 4.5 推理模型会把 token 花在看不见的地方

第一次跑画像，结果 `source=statistical`（降级）、耗时 19 秒、`usage.completion_tokens=0`。

查下来：本机配置的 `deepseek-flash` 是推理模型，`max_tokens=1200` 时
`finish_reason=length`、`reasoning_tokens=1200`、**正文长度 0**。

| max_tokens | reasoning_tokens | 正文长度 | 结果 |
|---|---|---|---|
| 1200 | 1200 | 0 | 空内容 → 解析失败 |
| 8000 | 7057 | 1140 | 正常 |

修正三处：预算提到 8000；**空内容要主动报错**（`LlmUnavailable`）而不是交给解析器；
降级时把原因写进 `fallback_reason`，界面直接显示。
第一版没有这个字段 —— 用户只看到"纯统计画像"，看起来像设计选择，其实是失败。**静默降级比报错更坏。**

### 4.6 "拒答"要区分完全拒答和部分覆盖

实测一处真实回答：

> 资料只说明 KMO 和 Bartlett 用于检验变量间相关性是否足够……**资料未覆盖 KMO 统计量的具体含义**。【u001:p23】

这条答案是**有效**的（答了资料里有的部分），但初版 `denied` 只要文本里出现"资料未覆盖"就为真，
界面会挂一条"拒答"横幅，用户以为白问了。

修正判定：`denied = 没有检索结果 or (声明未覆盖 且 零引用)`。

### 4.7 领域措辞怎么"补充项目内容"

三处落点，都能说清"补了什么"：

1. **prompt 注入**：`profile.prompt_block()` 把领域名 + 前 12 个术语写进 instructions，要求"回答时优先使用这些术语本身"。只放术语不放说明 —— 说明是概括，放进 prompt 会被模型当事实继续引用。
2. **system 换人称**：从"数据挖掘课程的助教"换成"《多元统计分析》这份资料的助教"，避免领域漂移。
3. **检索扩展**：问题与画像里的"可能怎么问"Jaccard ≥ 0.45 时，把该问题标注的术语并入检索词。**只在首轮零命中时触发** —— 命中时不扩展，免得用一个"差不多的问题"污染本来正确的排序。

## 5. 异常处理矩阵

统一错误体 `{"error": {"code", "message", "hint"}}`，前端只读 `hint` 就能说人话。

| code | HTTP | 触发 | 用户看到 |
|---|---|---|---|
| `unsupported_type` | 415 | 非 pdf/txt/md | 只接受 .pdf / .txt / .md |
| `file_too_large` | 413 | >50 MB | 单个文件上限 50 MB |
| `empty_file` | 400 | 0 字节 | 文件是空的 |
| `corrupt_file` | 422 | 无 `%PDF-` 文件头 / 解析崩 | 可能改过扩展名 |
| `encrypted_pdf` | 422 | 带打开密码 | 先另存为不加密副本 |
| `no_text_layer` | 422 | 平均每页 <20 字符 | 扫描件，需先 OCR |
| `duplicate_doc` | 409 | sha256 命中已有 | 已上传过，doc_id=xxx |
| `too_many_docs` | 429 | >200 份 | 先删不用的 |
| `doc_not_found` | 404 | doc_id 不存在 | 刷新列表 |
| `empty_question` | 400 | 空白问题 | 说一句想问什么 |
| `bad_top_k` | 400 | top_k 不在 1~10 | 一般用 5 |
| `llm_not_configured` | 503 | 缺密钥 | `.env` 里写 `LLMKIT_API_KEY` |
| `llm_unavailable` | 503 | 模型空返回/不可达 | 画像退回纯统计，术语仍带出处 |

**安检顺序**（后缀 → 大小 → 魔数 → 解析 → 文本量）不是随意排的：
前三个不用打开文件，最便宜；"有没有文本层"只能解析完才知道。
反过来写，一个 2 GB 的假 PDF 会先被完整读进内存再告诉你格式不对。

上传接口按 1 MB 分块读流，超过上限立刻中止 —— `await file.read()` 会把整个文件先读进内存。

## 6. 实测数据（2026-11-18，本机）

样本：一份 30 页中文简答资料，43662 字符（23528 汉字），切成 59 块。

| 项目 | 结果 |
|---|---|
| 解析 | 30 页 / 59 块 / 0.3 s（含缓冲，重复访问走内存缓存） |
| 中文检索 | hit@1 **10/10**、hit@3 **10/10**、MRR **1.000** |
| 术语候选 | 443 个（freq≥3 / PMI≥2.0 / 熵≥1.0），Top 40 人工抽检 37 个是本领域术语 |
| 画像（真实模型） | 16 个术语、5 条提问措辞、rejected **0**、notes_dropped **0** |
| 画像成本 | ¥0.032 / 19.5 s（输出 3222 token，其中推理占大头） |
| 问答（真实模型） | 3 道资料内问题全部答对且引用正确；2 道资料外问题 **2/2 拒答** |
| 问答成本 | ¥0.010 / 2.8 s（单题） |
| 引用越界 | 5/5 题 `unsupported = ()` |
| 测试 | **393 passed**（原 283 + 新增 110）；无中文样本时 381 passed + 12 skipped |

一次真实画像的片段（原样摘录）：


## 7. 限制（明确到"什么情况下会不好用"）

1. **扫描件不行**：没有文本层直接 422。要支持得加 OCR，属于另一个工程量级。
2. **中文同义词靠不住**：资料写"协差阵"、用户问"协方差阵"，二元组只重合"方差"，排名会掉。缓解办法是画像里的措辞扩展，但它只覆盖"资料自己的说法"。
3. **小样本术语质量下降**：<2000 汉字时频次门槛降到 2，候选偏碎。这类词表应当当"候选"看，不能当结论。
4. **多文档共用一个 BM25 池**：20 份无关资料混在一起，某词在所有文档都常见 → IDF 被压低。真正的多文档库需要"一库一索引"或检索后按 doc_id 过滤。
5. **单进程、同步、无鉴权**：只绑 `127.0.0.1`。`ask()` 阻塞 2~3 秒，多人用会排队。
6. **表格 / 公式**：沿用 M2 的限制，表格竖排、公式常有乱码字符（中文数学 PDF 尤其明显）。
7. **验收测试依赖本机样本**：`test_acceptance_cn.py` 用 `LLMKIT_CN_SAMPLE` 指定样本，没有就跳过（12 skipped）。CI 里要跑得自己带样本。
8. **画像不会自动重建**：上传新资料后，旧资料的画像仍然基于旧的候选池。术语统计是全库的，重建是显式动作。

## 8. 怎么用

### 命令行

```bash
uv sync --extra web            # 装 fastapi / uvicorn / python-multipart
python -m studio               # http://127.0.0.1:8000
python -m studio --port 9000
```

浏览器打开首页即可：拖入文件 → 看术语表 → 点"生成画像" → 提问。

### 界面

单页、零构建、零外链（`studio/static/index.html`，约 900 行含样式与脚本）。断网可用，因为不引任何 CDN。

**布局**按"主任务在上"排：左栏是资料库（上传 + 文档卡片），右栏第一张卡片就是提问，
术语与画像折进下面的标签页。之前把术语表放最上面，20 条术语加 16 条画像会把输入框推到
900px 以下，用户得先滚一屏才能提问。

| 交互 | 行为 |
|---|---|
| 上传 | 点击 / 拖入都行；拖拽时整块高亮；失败后显示原因 + 「重试」，同时仍可点空白处换文件 |
| 健康状态 | 每 15 秒轮询（页面隐藏时暂停），服务重启后绿点自动恢复，不用刷新 |
| 引用 | 答案里的 `【u001:p18】` 渲染成可点标签，点一下滚到对应依据并高亮 1.6 秒 |
| 越界引用 | 出现在 `unsupported` 里的引用标红加删除线，顶部另挂一条红色横幅 |
| 拒答 | 挂黄色横幅，明确写"这是设计内的拒答，不是出错" |
| 空库 | 提问按钮置灰，右上角提示"先上传资料" |
| 可分享 | `#doc_id` 定位文档、`?q=...` 自动提问、`?tab=profile` 直接开画像页 |

**答案渲染**：模型返回的是轻量 markdown，页面只认三种结构（`**粗体**`、`【doc:pN】` 引用、
空行分段），先 `escape` 再替换，不给注入留口子。

**LaTeX 降级**（`deTeX()`）：模型有时会把公式写成 `\(\Gamma\)`、`\frac{a}{b}`、`\sum_{j} γ`。
页面没有公式引擎，直接显示就是一屏反斜杠。处理是两层：

1. `qa/prompt.py` 的规则 5 明确要求"不要输出 LaTeX，用纯文本和 Unicode 符号"——这是治本；
2. 前端仍做一次降级（去定界符 → 希腊字母与算符换符号 → `\frac` 按括号配对转 `(A)/(B)` → 压平上下标），
   因为模型不保证听话。实测四条样例：

```
\frac{\sum_{i}(x_i-\bar{x})^2}{n-1}   →  (∑_i(x_i-x̄)^2)/(n-1)
\frac{\frac{1}{2}}{3}                  →  ((1)/(2))/(3)
\alpha=0.05,\ \beta \in [0,1]          →  α=0.05, β ∈ [0,1]
hi²(B)=∑ⱼbᵢⱼ²（已是 Unicode）          →  原样不变
```

**响应式**三档断点：

| 宽度 | 变化 |
|---|---|
| ≤ 1080px | 两栏变单栏，术语/画像取消内部滚动（嵌套滚动在触屏上很难用） |
| ≤ 720px | 术语行变单列；提问栏折成三行（输入框 / 范围下拉 / 取前 N 条 + 按钮）；`input` 字号提到 16px 防 iOS 聚焦缩放 |
| ≤ 420px | 标签页与卡片头部间距收紧，数字框变窄 |

验证方式：用 iframe 固定 390px 宽模拟手机视口后截图（headless 的 `--window-size` 与
实际布局视口不一致，直接截会把右侧裁掉，看到的是假溢出）。

### HTTP 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 服务状态、文档数、模型名 |

## 9. 上生产前必须做的三件事

1. **加鉴权**。当前任何人都能读全库。至少要有 token 或反代层的基本认证。
2. **索引隔离**。按文档集建独立 BM25 索引（或换倒排/向量），否则多文档互相稀释 IDF。
3. **把画像生成挪出请求线程**。19 秒的同步调用会占满 worker；应改成后台任务 + 轮询状态。

这三件事都不难，但它们改变的是"谁能用""能放多少资料""能几个人同时用"，
不是"准不准"。当前版本把"准不准"和"可不可验证"解决了，剩下的属于部署问题。
